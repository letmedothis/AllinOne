# AllinOne 全量静态代码审查报告（代码逻辑 Bug 专项）

> 审查日期：2026-08-26
> 审查方式：全量静态审查（9 个并行子代理 + 5 个补充子代理 + 人工抽验关键发现），范围覆盖后端 8 个模块（326 个 Java 文件）、前端 214 个 .ts/.vue 文件、32 个 Mapper XML、6 份 SQL 脚本。
> 说明：仅报告**代码逻辑层面**的 bug（NPE、条件错误、越权、事务、并发、SQL/MyBatis 契约、前后端契约等），不含风格/性能建议。每条均给出文件+行号+证据。

## 总体结论

共确认 **89 条**逻辑问题（10 条高危 / 59 条中危 / 20 条低危；含人工复核新增、并排除 1 条误报）。

**最严重的系统性发现**：5 个业务 Mapper XML 的 resultMap 把 `del_flag` 列映射到实体上**不存在的 `delFlag` 属性**（且全局 `mapUnderscoreToCamelCase=false`）。MyBatis 在查询返回任何一行时即抛 `ReflectionException: There is no setter for property named 'delFlag'`，导致 **collect_category / collect_data / collect_template / collect_field_mapping / report_config 的列表与详情接口全部 500**——即数据收集、填报、模板、字段映射、报表配置五大核心功能的查询链路当前不可用。这属于上线前必须修复的 P0。

## 一、P0 / 高危问题

### 1.1 resultMap 映射不存在的 `delFlag` 属性 → 核心业务查询全部抛异常（系统性，5 处）

`mapUnderscoreToCamelCase` 在 `allinone-admin/src/main/resources/mybatis/mybatis-config.xml:17` 被注释（RuoYi 默认 false），显式 resultMap 按属性名反射调用 setter，属性不存在即抛 `ReflectionException`。

| 文件 | 行 | 实体是否含 delFlag |
|---|---|---|
| allinone-collect/src/main/resources/mapper/collect/CollectCategoryMapper.xml | 13 | ❌ CollectCategory 无 |
| allinone-collect/src/main/resources/mapper/collect/CollectDataMapper.xml | 19 | ❌ CollectData 无 |
| allinone-collect/src/main/resources/mapper/collect/CollectTemplateMapper.xml | 16 | ❌ CollectTemplate 无 |
| allinone-collect/src/main/resources/mapper/collect/CollectFieldMappingMapper.xml | 21 | ❌ CollectFieldMapping 无 |
| allinone-report/src/main/resources/mapper/report/ReportConfigMapper.xml | 18 | ❌ ReportConfig 无 |

受影响接口（列表/详情返回行即 500）：`/collect/category/list`、`/collect/data/list`、`/collect/data/{id}`、`/collect/template/list`、`/collect/template/{id}`、`/collect/mapping/list`、`/report/config/list`、`/report/config/{id}` 等；`CollectDataController.edit` 的"改后回查"也会在提交成功后 500。

**修复**：删除各 resultMap 中的 `<result property="delFlag" column="del_flag"/>` 行（实体无此字段，逻辑删除由 SQL 的 `del_flag='0'` 条件处理即可）；或在实体中补 `delFlag` 字段。

### 1.2 报表 Sheet 编辑以"数据范围可见"为门槛，可越权改删他人报表（collect）

- `WorkReportController.saveSheet`（`WorkReportController.java:93-168`）：仅用 `selectWorkReportById`（`@DataScope` 数据范围过滤）判报表存在，随后以 `selectAccessibleSheets`（`WorkReportSheetServiceImpl.java:51-74`，条件含部门数据范围 `buildDataScopeCondition`，XML `WorkReportSheetMapper.xml:41-63`）为可编辑集合。
- `saveCells`（`WorkReportController.java:214-217`）：同样用 `selectAccessibleSheetById` 判编辑权。
- 后果：同部门且数据范围为"本部门"的用户 B，无需 A 任何显式授权即可改/增/删 A 报表的 Sheet 并改写单元格；且新建 Sheet 的 `user_id` 记为 B（`WorkReportSheetServiceImpl.java:120`），导致 A（报表属主）反而无法对该 Sheet 分配/撤销权限（`grantPermission` 校验 `sheet.userId==当前用户`，`WorkReportController.java:250-251`）——**属主关系被反转**。
- 与 `WorkReportServiceImpl.requireOwner()`（`WorkReportServiceImpl.java:111-122`，注释明确"仅创建者本人或管理员可编辑/删除……其他用户应通过 Sheet 显式授权"）自相矛盾。

**修复**：saveSheet/saveCells 增加属主或显式授权校验（报表属主/管理员/存在 work_report_sheet_permission 授权），不能把数据范围可见性当作编辑权限。

### 1.3 WorkReportSheetPermission 查询 `SELECT *` + resultType，字段全部为 null（sql 交叉核对）

`WorkReportSheetPermissionMapper.xml:16-23` 的 `selectBySheetId`/`selectByTarget` 用 `SELECT * ... resultType="WorkReportSheetPermission"`。在 `mapUnderscoreToCamelCase=false` 下，`sheet_id/perm_type/perm_id/granted_by/create_time` 无法映射到实体的 `sheetId/permType/permId/grantedBy/createTime`，返回对象所有字段为 null → `GET /collect/report/permissions/{sheetDbId}` 权限列表永远为空，前端授权记录展示失效。

**修复**：改为显式列名 + resultMap（或开启驼峰映射）。

### 1.4 `updateUser` 丢失 deptId 判空 → 静默把用户部门置 NULL（system）

`SysUserMapper.xml:183`：`<if test="deptId != 0">dept_id = #{deptId},</if>`（上游 RuoYi 为 `deptId != null and deptId != 0`）。OGNL 中 `null != 0` 为 true，故请求体未传 deptId（如部分字段更新、第三方调用）时会把 `sys_user.dept_id` 静默置 NULL，用户失去部门归属，数据权限（按部门过滤）随即失效。配套的 `insertUser`（`SysUserMapper.xml:149-170`）列条件用 `!= 0`、值条件用 `!= ''`，deptId=0 时列数≠值数导致 SQL 报错。

**修复**：两处条件统一为 `deptId != null and deptId != 0`。

### 1.5 在线用户权限缓存刷新覆盖不全（角色停用/数据权限变更不生效，且整对象覆盖有竞态）（framework/system/admin）

- `SysRoleController.edit` 会调 `refreshPermissionByRoleId`，但 **dataScope / changeStatus / remove**（`SysRoleController.java:141-172`）均不刷新；角色被停用后，在线用户 Redis 中仍是旧权限且每次请求 `verifyToken` 续期，可继续持权操作直到重新登录。
- 即便刷新，`TokenService.refreshPermissionByRoleId`（`TokenService.java:336-365`）只重写 `permissions`，**不重新加载 `user.getRoles()` 的 dataScope**，`DataScopeAspect` 用的还是旧数据范围 → 数据权限降级/升级不生效。
- `JwtAuthenticationTokenFilter.java:37` 每请求 `verifyToken` 整对象写回，与 `refreshPermissionByRoleId` 的新权限写回存在覆盖竞态（旧快照可把新权限覆盖回去）。

**修复**：dataScope/changeStatus/remove 后同样刷新；刷新时重新加载用户角色（含 dataScope）；权限与登录时间拆分存储避免整对象覆盖。

### 1.6 `/jmreport`、`/jimubi`、`/drag` 匿名放行 + URL 参数/Cookie 携带 JWT，令牌泄露面大（framework/admin）

- `SecurityConfig.java:109` 对三个引擎前缀 `permitAll`；`TokenService.getToken`（`TokenService.java:262-288`）对这三个路径接受 `request.getParameter("token")` 与 `Admin-Token` Cookie。
- 前端把 JWT 拼在 iframe URL query（`/jmreport/view/xx?token=xxx`），URL 会进 Referer 头/访问日志/浏览器历史；而 `createToken`（`TokenService.java:195-201`）构造的 JWT **未设 exp 声明**，仅靠 Redis 30 分钟 TTL 兜底。
- 拿到泄露 URL 的人在该 TTL 内可直连引擎前缀读取报表（JimuReport 报表可执行报表 SQL）。

**修复**：JWT 加 exp；对引擎路径校验 Referer 域名；改用一次性短时 ticket 而非 URL 传 JWT；access-log 不记录 query。

## 二、中危问题

### collect 模块
- **回写引擎取显示文本而非原始值**（`DataWriteBackServiceImpl.java:177-181`）：`value = displayValue != null ? displayValue : rawValue`，格式化单元格（如 `m='1,234.56'`、`v=1234.56`）会把显示文本写入目标表；且忽略 `dataType` 全部按 String 传参 → DECIMAL 列在严格模式下插入失败致整体事务回滚，VARCHAR 列则写入错误数据（与 Tier2 取 `v` 口径不一致）。
- **模板删除保护只统计非草稿数据**（`CollectTemplateServiceImpl.java:74-85` + `CollectTemplateMapper.xml:88-93`）：模板下存在草稿时允许删模板，删后草稿仍可 `submit` 成"模板已软删"的孤儿已提交数据（`CollectDataServiceImpl.submitData` 不校验模板存在/发布状态）。
- **CollectFieldMappingMapper 接口与 XML 绑定缺失**（`CollectFieldMappingMapper.java:12,14` vs XML）：声明的 `batchUpsert`、`deleteCollectFieldMappingByTemplate` 在 XML 中无对应语句，一旦调用即 `BindingException`。
- **填报分类删除不检查子分类**（`CollectCategoryServiceImpl.java:45-52`）：删父分类后遗留孤儿子分类（parent_id 指向已软删节点），子分类下模板不受保护。
- **分类可成环、ancestors 从不维护**（`CollectCategoryServiceImpl.java:30-43` + `CollectCategoryMapper.xml:50`）：parentId 可改为自身/子孙；insert/update 都不计算 ancestors。
- **填报数据软删不级联 collect_data_cell**（`CollectDataServiceImpl.java:126-138`）：`deleteCollectDataByIds` 只软删主表，单元格（del_flag='0'）仍可被查到，已删除填报仍计入报表统计，长期堆积无用行。
- **grant() 幂等存在竞态**（`WorkReportSheetPermissionServiceImpl.java:16-24`）：exists→insert 非原子，并发重复授权撞唯一约束抛未捕获异常 → 500。
- **`insertCollectData`/`submitData` 不校验 templateId 存在/已发布**（`CollectDataServiceImpl.java:56-67,90-124`）：可对不存在或未发布模板填报，产生孤儿数据。

### report 模块
- **分类批量删除无事务**（`ReportCategoryServiceImpl.java:49-60`）：多个 id 逐个删除，中途抛异常则部分删除。
- **分类删除保护未覆盖子分类**：同 collect 分类问题（父分类删除后子分类孤儿）。
- **分类 parentId/ancestors 未校验未维护**：同 collect 分类（`ReportCategoryMapper.xml` 与 `ReportCategoryServiceImpl`）。
- **byId/update 不过滤 del_flag**（`ReportConfigMapper.xml:31` `selectReportConfigById` 无 `del_flag='0'`）：已软删的报表仍可取到/更新；`updateReportConfig` 同样无 del_flag 条件。
- **唯一键冲突未处理**：`report_code` 若建唯一索引，重复插入抛原始异常。

### system 模块
- **公告未读数统计口径错误**（`SysNoticeController.java:93-95`）：`listTop` 只在最新 5 条内统计未读；全量统计方法 `selectUnreadCount`（`SysNoticeReadServiceImpl.java:38-42`）从未被调用 → 公告>5 条时未读角标失真。
- **公告删除两步无事务**（`SysNoticeController.java:147-148`）：先删 `sys_notice_read` 再删 `sys_notice`，第二步失败则已读记录丢失而公告仍在。
- **字典改类型后旧类型缓存未清理**（`SysDictDataServiceImpl`）：变更 dict_type 的字典数据时只删新类型缓存。

### framework 模块
- **JmReportTokenServiceI 契约未完整实现**：`getDictItems/getRoleList/getUserList/getTenantId/customApiHeader` 走引擎默认实现（已通过反编译 `jimureport-spring-boot3-starter 2.5.0` 确认接口存在这些方法）→ 设计器字典回显、用户/角色选择器、多租户不可用；`getUserInfo`（`JimuReportTokenService.java:75-84`）返回键（username/user_id/dept_id/roles）与接口约定键（sysUserCode/sysOrgCode/sysDate/sysDateTime）不一致，报表 SQL 内置参数取不到值。
- **`getPermissions` 与引擎精确匹配不兼容**：sys_menu 权限集中无 `jmreport:*`/`drag:*` 权限，admin 的 `*:*:*` 通配对引擎的 `@RequiresPermissions`（精确 equals）无效；开启设计器后报表保存/数据源等受权限保护操作对所有人 403。
- **数据权限变更后在线缓存不刷新**（`DataScopeAspect` 从 Redis 缓存的 role.dataScope 取条件，`TokenService.refreshPermissionByRoleId` 不重载 roles）——见 1.5。

### common 模块
- **SensitiveJsonSerializer.createContextual 返回共享实例 this**（`SensitiveJsonSerializer.java:39-49`）：多个 `@Sensitive` 字段复用同一实例，脱敏类型互相覆盖（上游 RuoYi-Vue-Plus 已确认并修复）。当前无字段使用该注解，属潜伏缺陷。
- **RedisCache.keys() 全量阻塞扫描**（`RedisCache.java:264-267`）：被在线用户列表、缓存管理、配置清理等请求路径直接调用，key 多时阻塞 Redis。

### quartz 模块
- **`changeStatus` 对不存在的 jobId 直接 NPE**（`SysJobController.java:155-160`）：`selectJobById` 未判空即 `newJob.setStatus(...)` → 500。
- **`updateJob` 调度重建非原子**（`SysJobServiceImpl.java:221-250`）：先提交 DB，再 `scheduler.deleteJob` + `createScheduleJob`；后者抛异常（如 misfirePolicy 传非法值，add/edit 均未校验该字段）时 DB 回滚但调度器旧 job 已删新 job 未建 → 任务从调度器消失、DB 显示正常，重启前持续不一致；jobId 不存在时 `properties.getJobGroup()` 也 NPE。
- **add/edit 缺 `@Valid`**（`SysJobController.java:82-111,118-147`）：`SysJob` 上的约束注解全部失效；cronExpression 为 null → `CronUtils.isValid(null)` 抛 IllegalArgumentException；invokeTarget 为 null → `ScheduleUtils.whiteList(null)` 对 `split(null,".")[0]` NPE。
- **`run()` 可绕过暂停状态执行任务**（`SysJobServiceImpl.java:178-195`）：`scheduler.triggerJob` 不检查 trigger 的 PAUSED 状态，DB 暂停的任务点"立即执行"仍真实运行；DB 行已删但调度器残留时 `properties=null` 被放入 dataMap，执行期异常却返回成功。
- **`createScheduleJob` 中 `job.getStatus()` 未判空**（`ScheduleUtils.java:86-97`）：注册成功后判空 NPE → DB 回滚但调度器保留新配置，DB 旧 cron/调度器新 cron 分叉。
- **无效 cron 可致应用启动失败或列表接口 500**（`CronUtils.java:51-62`）：`getNextExecution` 抛 IllegalArgumentException；`init()`（`SysJobServiceImpl.java:39-48`）对任一条脏 cron 直接 PostConstruct 失败；`SysJob.getNextValidTime()` 被 Jackson 序列化调用，脏数据拖垮列表接口。
- **`JobInvokeUtil` 参数解析 NumberFormatException**（`JobInvokeUtil.java:106-145`）：`"3.14"`/`"2000l"`/空串等一律 `Integer.valueOf` 抛异常，仅运行时暴露。
- **`deleteJobByIds` 批量删除遇不存在 id 整批回滚**（`SysJobServiceImpl.java:139-148`）：`job=null` 时 `deleteJob(job)` NPE。
- **`init()` 的 `scheduler.clear()` 集群风险**（`SysJobServiceImpl.java:39-48`）：多实例/启用 JDBC 集群后互相清空、重复执行。
- **`AbstractQuartzJob.after()` 日志写入失败触发二次调用**（`AbstractQuartzJob.java:44-50,70-96`）：`addJobLog` 抛异常落入 catch 再次 `after(...)`，重复写日志并掩盖真实结果。
- **edit 缺 jobGroup 时任务被重建到 Quartz 默认组**（`SysJobServiceImpl.java:239-250`）：重建用请求体的 `job.getJobGroup()`（null → DEFAULT 组），后续按 DB 组 pause/resume/delete 全部落空，任务无法停止。
- **`pauseJob/resumeJob` 对从未调度的任务（过期 cron）行为不一致**（`SysJobServiceImpl.java:80-112`）：RAM store 下"恢复"静默成功但任务永远不会执行。

### admin / 控制器模块（补充）
- **`/unlockscreen` 解锁接口绕过登录失败锁定（中）**（`SysIndexController.java:43-63`）：直接用 `SecurityUtils.matchesPassword` 比对，不走 `SysPasswordService.validate`（无错误计数/锁定/验证码），也不校验账号 status/delFlag；登录接口 5 次失败锁定 10 分钟，该接口却可无限次猜密码（配合 1.6 的 token 泄露面，风险叠加）。
- **权限变更后在线用户缓存刷新机制不完整（中）**（`TokenService.java:336-365`）：刷新基于登录时 roles 快照且只重算 permissions——角色"停用"后快照 status 仍为 '0'，已停用角色权限无法撤销；角色删除、用户授权变更、菜单变更等入口均不触发刷新（与 1.5 合并）。
- **公告 markRead/markReadAll 未校验公告存在性与状态（低）**（`SysNoticeController.java:104-124`）：任意 noticeId 可写入已读记录；`sys_notice_read.notice_id` 为 `int(4)`，超 2147483647 触发 MySQL 1264 → 500。
- **`X-Access-Token` 头回退对所有业务接口生效（低）**（`TokenService.java:272`）：该回退不受 `allowEmbeddedToken` 限制，令牌接受面超出注释声明，与其它 jeecg 系应用共用 Redis/JWT 密钥时扩大泄露面。
- **`RefererFilter` 子串匹配可绕过（低）**（`RefererFilter.java:41-68`）：`referer.contains(domain)` 可被 `allowed.com.evil.com` 之类构造绕过；空配置时 `domains.split(",")` NPE（默认关闭，开启即存在）。

### generator 模块
- **`SqlUtil.filterKeyword` 黑名单整体失效（高）**（`SqlUtil.java:55-70`）：先 `replaceAll("\\p{Z}|\\s","")` 剥离全部空白，再对**带尾随空格**的关键字（`select `/`drop `/`or `/`union `/`insert ` 等 17 个）做 indexOf——在无空白的字符串上永远无法命中；连 `\u000B` 也被 `\s` 剥掉。`CREATE TABLE x AS SELECT * FROM sys_user` 可绕过校验。
- **`createTable` 以 `${sql}` 直接拼接执行（高）**（`GenTableMapper.xml:177-179` + `GenController.java:130-160`）：只按 `instanceof MySqlCreateTableStatement` 放行即执行 `toString()` 还原的整条语句，`CREATE TABLE ... AS SELECT ...`（可含 `database()`/`version()` 等函数）形成数据外带通道（该端点 admin-only，缓解但未消除）。
- **`columnList` 缺 `@PathVariable`（中）**（`GenController.java:99-108`）：`columnList(Long tableId)` 未注解，路径参数永不绑定（按 @RequestParam 处理），`/tool/gen/column/{tableId}` 恒返回空列表（上游 RuoYi 有注解，属回归）。
- **`createTable` 以"受影响行数 ==0"判成功（中）**（`GenTableServiceImpl.java:160-164`）：`CREATE TABLE ... AS SELECT` 返回行数>0 被误判失败；createTableSave 整体无事务，多条语句部分失败时产生"库有表、gen_table 无记录"不一致。
- **`GenTableColumn.isEdit()` 复制粘贴误调 `isInsert(this.isEdit)`（低）**（`GenTableColumn.java:236-239`）：当前两个重载行为一致故未显错，属潜伏复制粘贴缺陷。
- **`GenConfig` 用默认 `@PropertySource` 加载 YAML（低）**（`GenConfig.java:13-15`）：YAML 嵌套被按 properties 平面解析，与 `@ConfigurationProperties(prefix="gen")` 约定冲突，存在静默覆盖风险。
- **`selectDbTableListByNames` 空数组生成 `in ()` 非法 SQL（低）**（`GenTableMapper.xml:100-107`）：createTableSave 提交不含建表语句的 SQL 时触发。
- **表名/ID 未判空（低）**（`GenTableServiceImpl.java:295-299,373-377,487-504`）：`synchDb`/`previewCode`/`downloadCode` 对不存在表直接 `table.getColumns()` NPE；`setPkColumn` 无主键且列空时 `get(0)` 越界。

### SQL / Mapper XML 交叉核对（补充）
- **`collect_data_cell` upsert 的 update_time 赋值语义错误**（`CollectDataCellMapper.xml:6-21`）：INSERT 列不含 `update_time`（DDL 无默认值 → 新行恒 NULL），且 ON DUPLICATE 分支写 `update_time = values(create_time)`，把"创建时间"当"更新时间"。对比 `WorkReportCellMapper.xml:35,42` 用 `now()` 是正确做法。
- **`work_report_sheet` 的 byId/update 漏 `del_status=0` 过滤**（`WorkReportSheetMapper.xml:26-29,107-116`）：已软删 Sheet 仍可被 grant/revoke 权限、可被 update 改写（与 list/accessible 口径不一致）。
- **`collect_category`/`collect_field_mapping`/`report_category`/`report_config` 四个 byId 漏 `del_flag='0'` 过滤**（各自 XML 的 byId 查询）：软删记录仍可通过 getInfo 读取并编辑，逻辑删除路径失效。
- **`selectCollectDataVo` 左连接未过滤 `ct.del_flag`**（`CollectDataMapper.xml:30`）：已删模板的填报数据仍展示模板名/编码（对比 `ReportConfigMapper.xml:29` 的正确写法）。
- **`updateWorkReport` 的 where 无 `del_status=0`**（`WorkReportMapper.xml:83`）：已删报表仍可被 PUT 修改。
- **`ReportCategory` resultMap 不完整**（`ReportCategoryMapper.xml:5-12`）：selectVo 查出 remark/del_flag/create_by 等 10 列但 resultMap 仅 6 列，字段静默丢弃；update 不写 update_by。
- **`selectCollectDataList` 未 select `form_data`**（`CollectDataMapper.xml:26-31`）：列表对象 formData 恒为 null，属隐性契约（当前恰好无人用）。
- **`allinone_biz_update.sql` Phase 5 无幂等守卫**（`:84-86`）：无条件 DROP INDEX/ADD UNIQUE，与 Phase 6/7/8 的 information_schema 守卫不一致，旧库索引结构不同时脚本中断。
- **`collect_data_cell.sheet_index` 未声明 NOT NULL 却参与唯一键**（`allinone_biz.sql:96,112`）：MySQL 唯一索引允许多个 NULL 共存，某写入路径漏设 sheetIndex 时去重失效。
- **`collect_data.flow_instance_id` 死列**（`CollectDataMapper.xml:13` vs 查询列）：DDL 有列、resultMap 有映射，但所有 SQL 均不 select/insert，字段永远 null。

## 四、前端（Vue3 + TS）问题

### 高危
- **列表页接口失败后 loading 永久挂起**（`views/collect/data/index.vue:163-170`，同类：`collect/category/index.vue:173-178`、`collect/template/index.vue:213-220`、`collect/report/index.vue:154-161`、`report/category/index.vue:171-177`、`report/config/index.vue:246-253`）：`getList()` 只在 `.then` 中关闭 loading，axios 响应拦截器对非 200 一律 reject，`.then` 不执行 → 接口 500/401/超时后 v-loading 永久转圈、页面不可操作。
