# M3 数电票(蓝字)XML 解析契约

> 分支:`feat/m3-digital-invoice`;依据 V2.0 §6。
> 状态:**已按真实票样 `digital-invoice-01` 的结构校准**。入库夹具为打码副本 `digital-invoice-01.fixture.xml`(企业名/税号/票号/银行/签名等已替换为演示值,结构逐节点不变);含真实信息的原始文件不入库(见 .gitignore 与投放目录说明)。

## 1. 范围

- 只解析**数电票(全电发票)蓝字**结构化 XML;PDF/OFD 仅作附件存档,不解析内嵌数据。
- 保留 `DemoInvoice schemaVersion=1.0` 解析分支仅用于演示,不参与生产判断。
- 红字(冲红)、进项勾选、税务验真不在本版。

## 2. 与既有实现的边界

- `InvoiceXmlParser`(现有)继续承载 DemoInvoice 解析与**格式检测路由**;
- 新增 `DigitalInvoiceXmlParser` 承载数电票蓝字适配(当前为可调试骨架);
- 新增 `DigitInvoiceNumbers`:20 位"数电票号码"规范化与校验。

## 3. 归一化与校验(不依赖具体 schema)

| 项 | 规则 |
| --- | --- |
| 数电票号码 | 去除首尾空白;**20 位数字**(税务数电票号码),保留前导零;唯一键=销方税号+票号(沿用 V1.0 D05 / invoice_identities) |
| 销方/购方税号 | 大写化;格式校验仅做 15/18/20 位提示,不做真实性验证 |
| 金额 | 未税/税额/价税合计按 V1.0 §6.3 口径,人工确认后方可提交 |
| 单价/税率/单位差异 | 差异说明必填(V1.0 D10) |
| 明细行 | 原票商品名称/规格/单位/数量/单价/税率/未税金额/税额;关联订单行;提交时按入库批次自动分配 |

## 4. 适配器映射(已按真实票样校准)

`DigitalInvoiceXmlParser` 按 local-name 匹配(兼容命名空间前缀),字段来源如下:

| 目标字段 | 票样元素(相对根 `EInvoice`) |
| --- | --- |
| invoiceNumber | `TaxSupervisionInfo/InvoiceNumber`(与 `Header/EIid` 同值,20 位) |
| invoiceType | `Header/InherentLabel/GeneralOrSpecialVAT/LabelName`(专/普);回退 `EInvoiceType/LabelName`,再缺省"数电票" |
| issueDate | `TaxSupervisionInfo/IssueTime`(YYYY-MM-DD);回退 `EInvoiceData/BasicInformation/RequestTime` 前 10 位 |
| sellerName / sellerTaxId | `EInvoiceData/SellerInformation/SellerName`、`SellerIdNum` |
| buyerName / buyerTaxId | `EInvoiceData/BuyerInformation/BuyerName`、`BuyerIdNum` |
| amount / taxAmount / totalAmount | `BasicInformation/TotalAmWithoutTax`、`TotalTaxAm`、`TotalTax-includedAmount` |
| lines 各行 | 每个 `IssuItemInformation`:ItemName / SpecMod / MeaUnits / Quantity / UnPrice / Amount / TaxRate / ComTaxAm |

> 解析只做结构提取,金额口径校验(含舍入与差异说明)在人工确认与提交链路(服务端)执行;解析结果不代表税务验真。
> 附加:数电票号码经 `DigitInvoiceNumbers.require20Digits` 强制 20 位;唯一键仍为销方税号+票号(`invoice_identities`)。
