## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **命名规范** | 完全遵循 RuoYi 框架约定，表名小写+下划线 |
| **审计字段** | 所有业务表统一包含：`create_by`, `create_time`, `update_by`, `update_time`, `remark`, `del_flag` |
| **主键策略** | 统一使用雪花主键（Snowflake ID），类型 `bigint(20)`，由应用层算法生成，不依赖数据库自增 |
| **字符集** | 统一使用 `utf8mb4` |
| **逻辑删除** | 统一使用 `del_flag char(1) default '0'`（0=存在，2=删除） |
| **外键策略** | 不建物理外键，在应用层 Service 维护关联一致性 |
| **索引策略** | 编码字段建唯一索引，外键字段和频繁查询字段建普通索引 |
| **JSON 存储** | Luckysheet 数据使用 `longtext` 存储 JSON |

### 雪花主键说明

所有表的主键采用 **雪花算法（Snowflake ID）** 生成，类型为 `bigint(20)`，由应用层的 `IdGenerator` 组件生成，建表时去掉 `auto_increment`。

**雪花ID结构：** 1位符号位 + 41位时间戳 + 10位工作机器ID + 12位序列号 → 共64位整数

**优势：**
- 全局唯一，不依赖数据库自增，方便后续分库分表
- 趋势递增，MySQL InnoDB 聚簇索引性能良好
- 可反解时间戳，具备业务可读性

> ⚠️ **雪花ID 前端精度处理：** 雪花 ID（64 位 long）在 JavaScript Number 中有精度丢失风险（Number 安全整数范围仅 2^53）。解决方案：Spring Boot 全局配置将 Long 序列化为 String：
> ```yaml
> spring:
>   jackson:
>     serialization:
>       write-numbers-as-strings: true
> ```
> 前端统一以字符串类型处理 ID，后端接口接收 String 参数后转为 Long。前端 Axios 请求中也需确保 ID 参数不被转换为 Number。

**实现方式：**
- 在 `allinone-common` 模块中提供 `SnowflakeIdGenerator` 工具类
- Service 层在 `insert` 前调用 `IdGenerator.nextId()` 设置主键值
- 或使用 MyBatis-Plus 的 `@TableId(type = IdType.ASSIGN_ID)` 自动注入

```java
// 工具类使用示例
@Service
public class CollectTemplateServiceImpl implements ICollectTemplateService {
    @Autowired
    private IdGenerator idGenerator;
    
    @Override
    public int insert(CollectTemplate template) {
        template.setTemplateId(idGenerator.nextId());
        return templateMapper.insert(template);
    }
}
```

## 2. 表结构清单

### 2.1 填报模板表（collect_template）

**使用场景：** 存储 Luckysheet 在线表格的模板定义。管理员创建模板时写入一条记录，包含完整 Luckysheet JSON 配置。发布后用户基于此模板进行填报。支持多版本管理，每次修改发布自动递增版本号。

| 字段名 | 类型 | 说明 | 可空 |
|--------|------|------|:----:|
| `template_id` | bigint(20) | 模板ID，雪花主键 | ❌ |
| `template_name` | varchar(200) | 模板名称 | ❌ |
| `template_code` | varchar(64) | 模板编码（唯一），用于 URL 标识 | ❌ |
| `category_id` | bigint(20) | 所属分类ID，关联 collect_category | ✅ |
| `template_type` | char(1) | 模板类型：0普通，1带流程（V2.0启用） | ✅ |
| `template_json` | longtext | 模板JSON，Luckysheet 完整配置 | ✅ |
| `status` | char(1) | 发布状态：0未发布，1已发布 | ✅ |
| `version` | int(8) | 版本号，每次修改发布递增 | ✅ |
| `remark` | varchar(500) | 备注 | ✅ |
| `del_flag` | char(1) | 删除标志：0存在，2删除 | ✅ |
| `create_by` | varchar(64) | 创建者 | ✅ |
| `create_time` | datetime | 创建时间 | ✅ |
| `update_by` | varchar(64) | 更新者 | ✅ |
| `update_time` | datetime | 更新时间 | ✅ |

```sql
drop table if exists collect_template;
create table collect_template (
  template_id      bigint(20)      not null                   comment '模板ID',
  template_name    varchar(200)    not null                   comment '模板名称',
  template_code    varchar(64)     not null                   comment '模板编码',
  category_id      bigint(20)      default null               comment '所属分类ID',
  template_json    longtext                                   comment '模板JSON（Luckysheet完整配置）',
  template_type    char(1)         default '0'                comment '模板类型（0普通 1带流程）',
  status           char(1)         default '0'                comment '发布状态（0未发布 1已发布）',
  version          int(8)          default 1                  comment '版本号',
  remark           varchar(500)    default null               comment '备注',
  del_flag         char(1)         not null default '0'       comment '删除标志（0存在 2删除）',
  create_by        varchar(64)     default ''                 comment '创建者',
  create_time      datetime                                   comment '创建时间',
  update_by        varchar(64)     default ''                 comment '更新者',
  update_time      datetime                                   comment '更新时间',
  primary key (template_id),
  unique key uk_ct_code (template_code),
  key idx_ct_category (category_id),
  key idx_ct_status (status),
  key idx_ct_create_time (create_time)
) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '填报模板表';
```

**索引说明：**
- `uk_ct_code` — 模板编码唯一索引，防止编码重复
- `idx_ct_category` — category_id 普通索引，加速按分类查询模板
- `idx_ct_status` — status 普通索引，加速按发布状态过滤
- `idx_ct_create_time` — create_time 索引，加速模板列表按时间排序

### 2.2 填报数据表（collect_data）

**使用场景：** 存储用户通过 Luckysheet 提交的填报数据。每次填报提交生成一条记录，包含完整的 Luckysheet 单元格数据 JSON 快照（用于精确还原展示），以及业务状态用于跟踪数据生命周期。

| 字段名 | 类型 | 说明 | 可空 |
|--------|------|------|:----:|
| `data_id` | bigint(20) | 数据ID，雪花主键 | ❌ |
| `template_id` | bigint(20) | 所属模板ID，关联 collect_template | ❌ |
| `form_data` | longtext | 填报数据JSON，用户填写的单元格数据完整快照 | ✅ |
| `biz_status` | varchar(10) | 业务状态：draft草稿，submitted已提交 | ❌ |
| `dept_id` | bigint(20) | 所属部门ID，用于@DataScope数据权限过滤 | ✅ |
| `flow_instance_id` | varchar(64) | 关联流程实例ID（V2.0启用） | ✅ |
| `data_code` | varchar(64) | 业务编码（如 BUDGET-202607-0001） | ✅ |
| `version` | int(8) | 乐观锁版本号 | ✅ |
| `submit_by` | varchar(64) | 提交人登录名，对应 sys_user.user_name | ✅ |
| `submit_time` | datetime | 提交时间 | ✅ |
| `remark` | varchar(2000) | 备注（驳回原因等） | ✅ |
| `del_flag` | char(1) | 删除标志：0存在，2删除 | ❌ |
| `create_by` | varchar(64) | 创建者（创建草稿者） | ✅ |
| `create_time` | datetime | 创建时间 | ✅ |
| `update_by` | varchar(64) | 更新者 | ✅ |
| `update_time` | datetime | 更新时间 | ✅ |

```sql
drop table if exists collect_data;
create table collect_data (
  data_id          bigint(20)      not null                   comment '数据ID',
  template_id      bigint(20)      not null                   comment '所属模板ID',
  form_data        longtext                                   comment '填报数据JSON（Tier 1快照）',
  biz_status       varchar(10)     default 'draft'            comment '业务状态（draft草稿 submitted已提交）',
  dept_id          bigint(20)      default null               comment '所属部门ID',
  flow_instance_id varchar(64)     default null               comment '关联流程实例ID（V2.0）',
  data_code        varchar(64)     default null               comment '业务编码',
  version          int(8)          default 1                  comment '乐观锁版本号',
  submit_by        varchar(64)     default null               comment '提交人',
  submit_time      datetime                                   comment '提交时间',
  remark           varchar(2000)   default null               comment '备注（驳回原因等）',
  del_flag         char(1)         not null default '0'       comment '删除标志（0存在 2删除）',
  create_by        varchar(64)     default ''                 comment '创建者',
  create_time      datetime                                   comment '创建时间',
  update_by        varchar(64)     default ''                 comment '更新者',
  update_time      datetime                                   comment '更新时间',
  primary key (data_id),
  key idx_cd_template (template_id),
  key idx_cd_submit (submit_by, submit_time),
  key idx_cd_dept (dept_id),
  key idx_cd_creator (template_id, create_by),
  key idx_cd_del (del_flag, create_time),
  key idx_cd_biz (biz_status),
  key idx_cd_code (data_code)
) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '填报数据表';
```

**索引说明：**
- `idx_cd_template` — template_id 普通索引，加速按模板查询所有填报数据
- `idx_cd_status` — biz_status 普通索引，加速按业务状态过滤
- `idx_cd_submit` — (submit_by, submit_time) 联合索引，加速按提交人查询历史填报
- `idx_cd_dept` — dept_id 普通索引，支撑 @DataScope 数据权限过滤
- `idx_cd_creator` — (template_id, create_by) 联合索引，加速"我的填报"按模板筛选场景
- `idx_cd_del` — (del_flag, create_time) 组合索引，避免逻辑删除后的全表扫描
- `idx_cd_biz` — biz_status 索引，加速按业务状态过滤
- `idx_cd_code` — data_code 普通索引，加速业务编码检索

### 2.3 填报单元格数据表（collect_data_cell）

**使用场景：** 三层存储架构的 **Tier 2 单元格层**。每次保存填报数据时，将 `collect_data.form_data` JSON 中的 `celldata` 数组展开，每个单元格拆为一条记录。JimuReport 可直接 SELECT 查询此表，无需依赖字段映射。三层存储关系：

| 层级 | 表 | 用途 |
|:----:|----|------|
| Tier 1 快照 | `collect_data.form_data`（JSON） | 页面精确还原 |
| **Tier 2 单元格** | **`collect_data_cell`（关系型）** | **JimuReport 明细查询、行列筛选、跨表单统计** |
| Tier 3 业务 | `biz_xxx`（字段映射回写） | 业务报表、BI 分析 |

| 字段名 | 类型 | 说明 | 可空 |
|--------|------|------|:----:|
| `cell_id` | bigint(20) | 雪花主键 | ❌ |
| `data_id` | bigint(20) | 所属填报数据ID，关联 collect_data | ❌ |
| `template_id` | bigint(20) | 所属模板ID（冗余字段，避免频繁JOIN） | ❌ |
| `sheet_index` | int(4) | 工作表索引（多Sheet用） | ✅ |
| `row_index` | int(8) | 行号（0-based） | ❌ |
| `col_index` | int(8) | 列号（0-based） | ❌ |
| `cell_text` | text | 单元格显示文本（m值） | ✅ |
| `cell_value` | text | 单元格原始值（v值） | ✅ |
| `cell_numeric_value` | decimal(20,4) | 预解析数值（供聚合查询直接使用，避免 CAST） | ✅ |
| `cell_type` | varchar(20) | 单元格类型：string/number/date/boolean | ✅ |
| `cell_format` | varchar(50) | 数字格式，如 #,##0.00 | ✅ |
| `is_formula` | char(1) | 是否为公式（0否 1是） | ✅ |
| `formula_expr` | text | 公式表达式 | ✅ |
| `del_flag` | char(1) | 删除标志：0存在，2删除 | ❌ |
| `create_by` | varchar(64) | 创建者 | ✅ |
| `create_time` | datetime | 创建时间 | ✅ |
| `update_by` | varchar(64) | 更新者 | ✅ |
| `update_time` | datetime | 更新时间 | ✅ |

```sql
drop table if exists collect_data_cell;
create table collect_data_cell (
  cell_id            bigint(20)      not null                   comment '雪花主键',
  data_id            bigint(20)      not null                   comment '所属填报数据ID',
  template_id        bigint(20)      not null                   comment '所属模板ID（冗余字段）',
  sheet_index        int(4)          default 0                  comment '工作表索引',
  row_index          int(8)          not null                   comment '行号（0-based）',
  col_index          int(8)          not null                   comment '列号（0-based）',
  cell_text          text                                       comment '显示文本（m值）',
  cell_value         text                                       comment '原始值（v值）',
  cell_numeric_value decimal(20,4)   default null               comment '预解析数值',
  cell_type          varchar(20)     default null               comment '单元格类型',
  cell_format        varchar(50)     default null               comment '数字格式',
  is_formula         char(1)         default '0'                comment '是否为公式（0否 1是）',
  formula_expr       text                                       comment '公式表达式',
  del_flag           char(1)         not null default '0'       comment '删除标志（0存在 2删除）',
  create_by          varchar(64)     default ''                 comment '创建者',
  create_time        datetime                                   comment '创建时间',
  update_by          varchar(64)     default ''                 comment '更新者',
  update_time        datetime                                   comment '更新时间',
  primary key (cell_id),
  unique key uk_cdc_data_rc (data_id, row_index, col_index),
  key idx_cdc_template (template_id),
  key idx_cdc_sheet (data_id, sheet_index),
  key idx_cdc_tmpl_rc (template_id, row_index, col_index, sheet_index)
) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '填报单元格数据表（三层架构Tier 2）';
```

**索引说明：**
- `uk_cdc_data_rc` — (data_id, row_index, col_index) 唯一索引，用于增量 upsert（INSERT ... ON DUPLICATE KEY UPDATE）
- `idx_cdc_template` — template_id 索引，加速按模板查询所有单元格（跨表单统计）
- `idx_cdc_sheet` — (data_id, sheet_index) 联合索引，加速多Sheet场景
- `idx_cdc_tmpl_rc` — (template_id, row_index, col_index, sheet_index) 联合索引，覆盖 JimuReport 典型查询：`WHERE template_id=? AND row_index=? AND col_index=?`

**存储与性能策略：**
- `cell_value` 和 `cell_text` 使用 `text` 类型（支持最长 65535 字符），避免长文本截断
- `cell_numeric_value` 预解析数值字段，写入时自动去除千分位分隔符并转 DECIMAL，供 JimuReport 直接 SUM/AVG 查询
- 保存策略使用 **增量 upsert**：基于 `uk_cdc_data_rc` 唯一键，执行 `INSERT ... ON DUPLICATE KEY UPDATE`，避免频繁 DELETE+INSERT 产生的 undo log 和索引页分裂

### 2.4 填报分类表（collect_category）

**使用场景：** 填报模板的树形分类，支持多级层级（如：人事管理-考勤填报、财务管理-费用报销）。使用 `parent_id + ancestors` 方案实现高效树查询，参照 RuoYi 部门表设计。

| 字段名 | 类型 | 说明 | 可空 |
|--------|------|------|:----:|
| `category_id` | bigint(20) | 分类ID，雪花主键 | ❌ |
| `category_name` | varchar(100) | 分类名称 | ❌ |
| `parent_id` | bigint(20) | 父分类ID，顶级为0 | ❌ |
| `ancestors` | varchar(500) | 祖级列表，逗号分隔 | ✅ |
| `order_num` | int(4) | 显示顺序 | ❌ |
| `status` | char(1) | 状态：0正常，1停用 | ❌ |
| `remark` | varchar(500) | 备注 | ✅ |
| `del_flag` | char(1) | 删除标志：0存在，2删除 | ❌ |
| `create_by` | varchar(64) | 创建者 | ✅ |
| `create_time` | datetime | 创建时间 | ✅ |
| `update_by` | varchar(64) | 更新者 | ✅ |
| `update_time` | datetime | 更新时间 | ✅ |

```sql
drop table if exists collect_category;
create table collect_category (
  category_id      bigint(20)      not null                   comment '分类ID',
  category_name    varchar(100)    not null                   comment '分类名称',
  parent_id        bigint(20)      default 0                  comment '父分类ID',
  ancestors        varchar(500)    default ''                 comment '祖级列表',
  order_num        int(4)          default 0                  comment '显示顺序',
  status           char(1)         default '0'                comment '状态（0正常 1停用）',
  remark           varchar(500)    default null               comment '备注',
  del_flag         char(1)         not null default '0'       comment '删除标志（0存在 2删除）',
  create_by        varchar(64)     default ''                 comment '创建者',
  create_time      datetime                                   comment '创建时间',
  update_by        varchar(64)     default ''                 comment '更新者',
  update_time      datetime                                   comment '更新时间',
  primary key (category_id),
  key idx_cc_parent (parent_id),
  key idx_cc_order (parent_id, order_num),
  key idx_cc_status (status)
) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '填报分类表';
```

**索引说明：**
- `idx_cc_parent` — parent_id 普通索引，加速按父分类查询子分类
- `idx_cc_order` — (parent_id, order_num) 联合索引，加速同级分类排序展示
- `idx_cc_status` — status 普通索引，加速按状态过滤

### 2.5 报表配置表（report_config）

| 字段名 | 类型 | 说明 | 可空 |

| `report_name` | varchar(200) | 报表名称，展示在菜单或列表中 | ❌ |

) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '报表配置表';

### 2.6 字段映射配置表（collect_field_mapping）

**使用场景：** 定义 Luckysheet 单元格坐标与业务表字段的映射关系。当用户提交填报数据时，数据回写引擎根据此配置将 `collect_data_cell` 中的单元格数据提取出来，写入对应的业务表字段，使 JimuReport 可以通过 SQL 查询到结构化的业务数据。Tier 3 业务层的核心配置。

| 字段名 | 类型 | 说明 | 可空 |
|--------|------|------|:----:|
| `mapping_id` | bigint(20) | 雪花主键 | ❌ |
| `template_id` | bigint(20) | 关联模板ID | ❌ |
| `cell_ref` | varchar(20) | 单元格坐标（如 B3、C5），人工可读 | ✅ |
| `row_index` | int(8) | 行号（0-based），与 collect_data_cell 对应 | ❌ |
| `col_index` | int(8) | 列号（0-based），与 collect_data_cell 对应 | ❌ |
| `target_table` | varchar(100) | 回写目标表名，如 biz_budget | ❌ |
| `target_column` | varchar(100) | 回写目标列名，如 amount | ❌ |
| `data_type` | varchar(50) | 数据类型：string/number/date/amount | ✅ |
| `pk_order` | tinyint(1) | 主键顺序：0不是主键，1/2/3为主键第N部分 | ✅ |
| `default_value` | varchar(200) | 默认值（单元格为空时使用） | ✅ |
| `transform_type` | char(1) | 转换类型：0无，1格式化，2脚本，3Spring Bean | ✅ |
| `transform_script` | text | 转换脚本 | ✅ |
| `order_num` | int(4) | 处理顺序 | ✅ |
| `remark` | varchar(500) | 备注 | ✅ |
| `del_flag` | char(1) | 删除标志：0存在，2删除 | ❌ |
| `create_by` | varchar(64) | 创建者 | ✅ |
| `create_time` | datetime | 创建时间 | ✅ |
| `update_by` | varchar(64) | 更新者 | ✅ |
| `update_time` | datetime | 更新时间 | ✅ |

```sql
drop table if exists collect_field_mapping;
create table collect_field_mapping (
  mapping_id       bigint(20)      not null                   comment '雪花主键',
  template_id      bigint(20)      not null                   comment '关联模板ID',
  cell_ref         varchar(20)     default null               comment '单元格坐标（如B3）',
  row_index        int(8)          not null                   comment '行号（0-based）',
  col_index        int(8)          not null                   comment '列号（0-based）',
  target_table     varchar(100)    not null                   comment '目标表名',
  target_column    varchar(100)    not null                   comment '目标列名',
  data_type        varchar(50)     default null               comment '数据类型',
  pk_order         tinyint(1)      default 0                  comment '主键顺序（0非主键）',
  default_value    varchar(200)    default null               comment '默认值',
  transform_type   char(1)         default '0'                comment '转换类型（0无 1格式化 2脚本 3Bean）',
  transform_script text             default null               comment '转换脚本',
  order_num        int(4)          default 0                  comment '处理顺序',
  remark           varchar(500)    default null               comment '备注',
  del_flag         char(1)         not null default '0'       comment '删除标志（0存在 2删除）',
  create_by        varchar(64)     default ''                 comment '创建者',
  create_time      datetime                                   comment '创建时间',
  update_by        varchar(64)     default ''                 comment '更新者',
  update_time      datetime                                   comment '更新时间',
  primary key (mapping_id),
  unique key uk_cfm_rc (template_id, row_index, col_index),
  key idx_cfm_table (target_table, target_column)
) engine=innodb default charset=utf8mb4 collate=utf8mb4_general_ci comment = '字段映射配置表（三层架构Tier 3）';
```

**索引说明：**
- `uk_cfm_rc` — (template_id, row_index, col_index) 联合唯一索引，同一模板下不能有两个映射指向同一单元格
- `idx_cfm_table` — (target_table, target_column) 联合索引，加速按目标表查询映射关系

## 3. 表关系说明

### E-R 概览

```
collect_category (1) ──────< (N) collect_template (1) ──────< (N) collect_data (1) ──────< (N) collect_data_cell
                              │                                       │
                              │ (1)                                   │ (Tier 1: JSON 快照)
                              │                                       │ (Tier 2: 单元格行)
                              │                                       ▼
                              │                            collect_field_mapping (N)
                              │                                   │ 定义提取规则
                              │                                   ▼
                              │                            目标业务表 (biz_xxx)
                              │                                   │
                              │                                   ▼
                              │                            JimuReport SQL 查询
                              │
report_category   (1) ──────< (N) report_config
                              │
                              ├── jimu_report_id → jimu_report.id (type=0 报表)
                              └── jmbi_id → onl_drag_page.id (type=1 大屏 / type=2 仪表盘)
```

### 详细关系矩阵

| 源表 | 目标表 | 类型 | 关联字段 | 业务含义 |
|------|--------|:----:|----------|----------|
| collect_template | collect_category | N:1 | collect_template.category_id → collect_category.category_id | 一个分类下包含多个模板；null表示未分类 |
| collect_data | collect_template | N:1 | collect_data.template_id → collect_template.template_id | 一个模板可以被多次填报产生多条数据 |
| report_config | report_category | N:1 | report_config.category_id → report_category.category_id | 一个分类下包含多个报表配置 |
| report_config | JimuReport 内部表 | 弱引用 | report_config.jimu_report_id → jimu_report.id | 关联JimuReport的报表数据（不建物理外键） |

### 逻辑关联说明

- 所有外键在应用层（Java Service 层）维护，数据库不建物理外键
- 分类删除时应用层先检查是否被引用，或置空 category_id
- 删除模板时应用层应提示确认或级联逻辑删除关联数据
- JimuReport 表由 JimuReport 引擎自身维护，本系统只做配置关联
