## 一、总体结论

1. **commit 27ae6a5 自身引入 3 处编译错误，项目在该提交后从未通过编译**（`target/classes` 时间戳早于提交时间佐证）。该提交声称的全部后端修复实际均未生效过。
2. 除编译错误外，该提交的多个"修复"只完成了一半，且引入了 3 个新的可用性缺陷（24 小时强制踢线、30 分钟硬登出、权限变更裸 500）。
3. 部署文档（README / SQL_EXECUTION_ORDER.md）与实际 SQL、配置脱敏后的要求严重脱节，严格按文档操作**100% 无法登录和启动**。
4. 本轮已静态修复全部阻断级与高危问题（见第三节），并通过独立子代理逐符号复查确认无断引用。

## 四、遗留问题（本轮未修，建议后续处理）

1. **约 20 个前端页面的 loading 挂起**：`system/user|post|dept|role|menu|config|notice`、`monitor/job`、`tool/gen`、`system/dict/data.vue` 等仍是 `.then` 内关 loading、无 catch/finally 的旧写法，接口失败页面永久转圈（上次报告 H-03 只修了 collect/report 的 6 个页面）。
2. **Jimu 票据机制（H-7）**：需前后端联动改造（新增票据签发端点 + 前端 iframe 改造 + `verifyToken` 支持票据换 JWT），建议单独排期；在此之前 URL 传 JWT 的泄露面仍在。
3. **前端字段映射（mapping）功能不可达**：后端 `/collect/mapping` 5 个端点孤立存在，`api/collect/mapping.ts` 与页面缺失（`doc/审核分析报告.md:115` 却标 ✅），Tier 3 数据回写在 UI 上无法配置。
4. `SqlUtil.filterKeyword` 仍无调用方且正则存在 `\u000B` 退化缺陷（一旦接线会全拒绝）；建议删除或重写后再接入。
5. `incrementVersion` 为非原子 get+set（应改 Redis INCR），并发变更可能丢失递增；量级低，属既有代码。
6. `requireEditableSheet` 底层查询未过滤 `del_status`，已软删 Sheet 仍可通过编辑权校验（低危）。
7. 写回白名单 `COLLECT_WRITE_BACK_ALLOWED_TABLES` 默认空 → 配置了字段映射的模板无法提交（属配置门槛设计，建议在错误提示或文档中明确说明）。
8. `WorkReportController.saveCells` 对 `rowIndex/colIndex/sheetDbId` 的强转无校验，畸形报文会 500（容错问题）。
9. 文档一致性小项：`doc/1-设计文档/03-数据库表结构设计.md` 的 `report_type` 字典建议应为 `report_config_type`；`04-API接口与页面设计.md` §2.4 表格损坏；`REPORT_INTEGRATION_GUIDE.md` 遗漏 `POST /collect/report/export`、"未引入 fastjson2"表述不实。
