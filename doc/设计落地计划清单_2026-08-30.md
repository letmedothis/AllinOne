## 阶段一：安全与数据权限加固（P1，约 2–3 天）

### - [x] 1.1 填报数据部门级数据权限（0.5–1 天）
- **✅ 实施记录（2026-08-30）**：实施：service 层按角色数据范围生成过滤 SQL（collect_data 无 user_id 列，“仅本人”用 create_by 表达，空配置兜底为仅本人），mapper 以 ${params.dataScopeSql} 拼接；管理员不过滤；导出同口径。
- **现状**：`CollectDataServiceImpl.selectCollectDataList` 仅按 `createBy = 当前用户` 过滤；设计 02 §1.7 要求 `@DataScope(deptAlias = "cd")`。"部门经理查看本部门填报"场景不成立。
- **改动**：
  - `CollectDataController.list` 加 `@DataScope(deptAlias = "cd")`；
  - `CollectDataMapper.xml` 的 `selectCollectDataList` 加 `${params.dataScope}` 占位；
  - 前端"我的填报"页保留"仅看我的"开关（createBy 参数），与管理视图并存。
- **验收**：普通角色仅见本人数据；配了本部门数据范围的角色可见本部门；管理员全量。

### - [x] 1.2 模板状态后端强制 + 错误码 1001–1004（0.5–1 天）
- **✅ 实施记录（2026-08-30）**：实施：CollectErrorCode 常量落地（1001/1002/1003/1004），insert 强制校验模板存在且已发布，乐观锁/状态错误统一携带业务码；前端拦截器对非 200 码已展示后端消息，无需改动。
- **现状**：错误码体系（设计 01 §7.2）未落地；下架模板后，已打开的填报页仍可提交成功（后端不校验模板状态）。
- **改动**：
  - common 定义业务错误码常量：1001 模板不存在、1002 模板未发布不可用、1003 数据状态不允许修改、1004 版本冲突；
  - `insertCollectData` / `updateCollectData` / `submitData` 前置校验模板 `status='1'` 且未删除，违者抛 1002；
  - 乐观锁失败统一抛 1004（替换现有纯中文消息），`ServiceException` 携带 code；
  - 前端 `request.ts` 识别 1002/1004 给专门文案（1004 → "数据已被他人修改，请刷新"）。
- **验收**：下架模板后提交返回 1002；并发保存返回 1004；前端提示明确。

### - [x] 1.3 关闭 JimuReport token 旧通道（0.5 天）
- **✅ 实施记录（2026-08-30）**：实施：TokenService 移除 URL token 参数与 Admin-Token Cookie 通道（含 isJimuReportRequest/EMBEDDED_ENGINE_PATHS），新增 getHeaderToken 供引擎集成使用；前端本就仅走 ticket，回归零影响。
- **现状**：前端已走一次性 ticket，但 `TokenService.getJimuReportToken`（TokenService.java:340-365）仍允许 URL `token` 参数与 Cookie 携带 JWT 直访 `/jmreport/**`，构成 ticket 旁路。
- **改动**：移除 URL token / Cookie 通道，`JimuReportTokenService.getToken` 仅接受 ticket 换取的 JWT；先排查报表设计器内嵌预览等调用方无残留依赖。
- **验收**：携带 URL token 直访 `/jmreport/**` 被拒；ticket 全流程（报表/大屏/设计器）回归通过。

### - [x] 1.4 导出上限与文件清理对齐设计（0.5–1 天）
- **✅ 实施记录（2026-08-30）**：实施：上限 200 → 10 万条；新增 ExportFileCleanupTask @Scheduled（默认每日 03:30，cron 可配 allinone.collect.export.cleanup-cron）清理 24h 前的异步导出文件（仅匹配任务命名模式，不误删他类文件）。
- **现状**：设计为"单次 10 万行、导出文件 24h 清理"；实现是 `EXPORT_MAX_RECORDS = 200`（CollectDataServiceImpl.java:45）且同步/异步共用；无任何清理任务。
- **改动**：
  - 上限提升至 10 万行级（异步通道为主；同步接口收缩为小上限或下线，前端已统一走异步）；
  - 新增定时清理（quartz 或 `@Scheduled`）：清理 `RuoYiConfig.getDownloadPath()` 中超过 24h 的导出文件，并同步关闭过期 `collect_export_task` 记录。
- **验收**：异步导出数千条成功；24h 后文件与任务状态被清理。
