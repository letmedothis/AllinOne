# AllinOne 修复与验证总结（2026-08-28）

## 1. 工作范围

本轮在既有静态审查报告基础上，对项目代码、构建链、数据库升级脚本和历史文档进行复核，并处理影响编译、数据一致性、鉴权安全、依赖安全和发布可重复性的主要问题。

## 2. 已完成修复

### 2.1 前端统一构建

- 新增 `scripts/build-frontend.sh`，固定执行顺序为：安装并构建 Luckysheet，再安装并构建主前端。
- 提交 `allinone-luckysheet/package-lock.json` 和 `allinone-typescript/package-lock.json`，统一使用 `npm ci`。
- 更新 README 中的构建和依赖审计说明。

### 2.2 采集数据完整快照

- 提交数据时，先按 `data_id` 删除已有单元格快照，再批量写入当前快照。
- 空快照也会清除旧数据，避免已删除单元格残留。
- 删除采集草稿时同步删除单元格快照，并纳入事务。
- 新增空快照、写入失败回滚、删除草稿清理快照等测试。

### 2.3 鉴权与并发安全

- 报表和大屏不再把 JWT 放入 URL，统一使用短期 Jimu ticket。
- ticket 使用 Redis 原子读取并删除，避免并发重复消费。
- 授权版本号使用 Redis Lua 原子递增，并兼容旧序列化值。
- 上传文件大小和请求大小统一限制为 50 MB。

### 2.4 数据库升级和编译修复

- 调整增量 SQL：先补充 `sheet_index` 字段，再创建或重建相关唯一索引。
- 修复 Jimu ticket 过期时间类型不匹配导致的编译错误。
- 修复代码生成控制器缺少 `UtilException` 导入的问题。
- Maven Surefire 升级至支持 JUnit 5 的版本，解决此前构建显示成功但实际执行 0 项测试的问题。

### 2.5 回写字段显式类型转换

- 新增统一的 `WriteBackValueConverter`。
- 支持 `string`、`integer`、`decimal`、`date`、`datetime`、`boolean`。
- 兼容 `varchar`、`text`、`number`、`amount`、`bigint` 等历史别名，并在保存配置时归一化。
- 数字和日期优先使用 Luckysheet 原始值，文本使用显示值；金额使用 `BigDecimal`。
- 数字和日期的空字符串转换为 `NULL`；主键转换后为空时拒绝回写。
- 转换错误包含 Sheet、行列和目标字段上下文。
- 前端字段类型由自由输入改为受控下拉选项。

### 2.6 前端依赖安全治理

- 新增 `scripts/audit-frontend.sh`：默认检查生产依赖，高危和严重漏洞阻断发布；`--all` 检查完整开发工具链。
- `esbuild` 从 Luckysheet 运行依赖移至开发依赖，并精确批准其安装脚本版本。
- Luckysheet：jQuery 从 2.2.4 升级至 3.7.1，`@babel/runtime` 升级至安全版本。
- 主前端：Axios 升级至 1.20.0，js-cookie 升级至 3.0.8。
- 禁止使用 `npm audit fix --force` 进行未经回归的跨主版本批量升级。
