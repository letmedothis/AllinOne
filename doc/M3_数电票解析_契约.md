# M3 数电票(蓝字)XML 解析契约

> 分支:`feat/m3-digital-invoice`;依据 V2.0 §6。
> 状态:**真实票样未到位**——本文件先锁定范围/归一化/验收清单;字段映射以用户提供的脱敏真实数电票 XML 校准后回填(见 §5)。

## 1. 范围

- 只解析**数电票(全电发票)蓝字**结构化 XML;PDF/OFD 仅作附件存档,不解析内嵌数据。
- 保留 `DemoInvoice schemaVersion=1.0` 解析分支仅用于演示,不参与生产判断。
- 红字(冲红)、进项勾选、税务验真不在本版。

## 2. 与既有实现的边界

- `InvoiceXmlParser`(现有)继续承载 DemoInvoice 解析与**格式检测路由**;
- 新增 `DigitalInvoiceXmlParser` 承载数电票蓝字适配(当前为可调试骨架);
- 新增 `DigitInvoiceNumbers`:20 位"数电票号码"规范化与校验。

## 3. 归一化与校验(不依赖具体 schema)

| 项 | 规则 |
| --- | --- |
| 数电票号码 | 去除首尾空白;**20 位数字**(税务数电票号码),保留前导零;唯一键=销方税号+票号(沿用 V1.0 D05 / invoice_identities) |
| 销方/购方税号 | 大写化;格式校验仅做 15/18/20 位提示,不做真实性验证 |
| 金额 | 未税/税额/价税合计按 V1.0 §6.3 口径,人工确认后方可提交 |
| 单价/税率/单位差异 | 差异说明必填(V1.0 D10) |
| 明细行 | 原票商品名称/规格/单位/数量/单价/税率/未税金额/税额;关联订单行;提交时按入库批次自动分配 |

## 4. 适配器契约(待票样校准后定稿)

`DigitalInvoiceXmlParser` 需要从真实 XML 提取的字段(以票面为准,候选标签名待回填):

| 目标字段 | 真实票样中的来源 |
| --- | --- |
| invoiceNumber | 数电票号码(20 位) |
| invoiceType | 数电票类型标识(蓝字) |
| issueDate | 开票日期 |
| sellerName / sellerTaxId | 销售方名称/统一社会信用代码 |
| buyerName / buyerTaxId | 购买方名称/统一社会信用代码 |
| amount / taxAmount / totalAmount | 合计金额(未税/税额/价税合计) |
| lines[].name/specification/unit/quantity/unitPrice/taxRate/amount/taxAmount | 货物或应税劳务、服务清单行 |

> 当前骨架只做「识别 + 结构诊断」:结构不匹配时返回**可操作的错误**(列出已识别元素与缺失字段),不返回伪造解析结果;待真实票样提供后回填映射并替换为回归测试。

## 5. 验收清单(真实票样到位后执行)

1. 至少 1 张真实脱敏数电票(蓝字)XML → 全字段正确解析,20 位票号通过;
2. 含清单多行票 → 行数与金额合计正确;
3. 单价/税率小数与舍入 → 与 V1.0 §6.3 一致;
4. 重复票(同税号+票号)提交被拦截;
5. PDF/OFD 同批上传仅存档;
6. 结构异常/伪造 XML → 明确报错,不产生半成品数据。

## 6. 待用户提供

- 1–3 份脱敏真实数电票 XML(含 1 份多行样例),放到仓库(建议 `allinone-supply/src/test/resources/invoices/`)并告知路径。
