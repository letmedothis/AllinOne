# M4 付款 / 应付核销 —— 设计

> 分支:`feat/m4-payment`;依据 V2.0 §5(已签认口径)。
> 已确认:审批链「采购部申请 → 财务复核(≤10 万直通)→ 财务总监终审(>10 万)」;单公司;不迁移历史(期初应付按少量发票人工补录)。

## 1. 应付来源与余额

- 应付 = 发票**财务审核通过(APPROVED)且未作废**的票面价税合计(`documents`+`invoices`);
- 发票应付余额 = `total_cents − Σ(已核销金额)`;
- 已核销金额 = 关联该发票、状态为 `IN_REVIEW/APPROVED` 且未删除的付款单明细合计(含本单在途占用),防止超付与重复。

## 2. 数据模型

### payments(付款单)

| 列 | 说明 |
| --- | --- |
| id | 主键 |
| number | `PAY-yyyyMMdd-NNNNN`(number_sequences document_type='PAYMENT') |
| supplier_id | 收款供应商(documents SUPPLIER id) |
| amount_cents | 申请付款总额(分) |
| threshold_exceeded | '0'=≤10 万 / '1'=>10 万(提交时由服务端计算) |
| status | DRAFT 草稿 / IN_REVIEW 审批中 / RETURNED 退回 / APPROVED 已付款(核销生效)/ VOID 作废 |
| current_node | FINANCE_REVIEW / FINANCE_DIRECTOR(仅审批中非空) |
| creator_id / creation_key / revision | 创建人/幂等键/乐观锁 |
| remark | 申请说明 |
| review_comment / director_comment | 财务复核 / 总监意见 |
| create_time / update_time / deleted | 审计时间与软删 |

### payment_lines(核销明细)

| 列 | 说明 |
| --- | --- |
| id | 主键 |
| payment_id | 付款单 |
| invoice_id | 发票(documents INVOICE id) |
| allocated_cents | 核销金额(分) |

约束:`UNIQUE (payment_id, invoice_id)`;校验:行合计=付款总额;单发票累计核销 ≤ 该发票应付余额;发票必须 APPROVED 且未作废;禁止对同一发票重复/超额。

## 3. 审批流(金额分档,固定流程,不入 Flowable 引擎)

- `金额 ≤ 100_000` 元:提交 → 财务复核通过 → **APPROVED(核销生效)**;
- `金额 > 100_000` 元:提交 → 财务复核通过 → 财务总监终审通过 → **APPROVED**;
- 任一节点退回 → RETURNED,释放核销占用,提交人修改后重新提交。
- 复核人 = 启用且非提交人的 `finance` 角色用户(沿用 selectEligibleFinanceCount 口径);
  终审人 = 启用、`finance` 角色且 `rank_level='EXEC'`、非提交人/复核人的用户(总监);
- 无合法候选 → 提交失败,不产生空待办。

> 说明:付款审批暂在付款管理模块内闭环(自己的待办视图),不并入旧"审批中心"与 Flowable,避免双引擎再叠加;后续如要统一待办再扩展。

## 4. 事务与并发(同 V1.0 13 原则)

- 提交/通过在单事务内完成:余额校验(`select … for update` 锁发票行)与占用写入同事务;
- 幂等:`creation_key` 唯一,重复提交拒收;前端按钮 @RepeatSubmit;
- 乐观锁 `revision`;状态迁移仅允许合法前驱(DRAFT/RETURNED→IN_REVIEW;IN_REVIEW→APPROVED/RETURNED;DRAFT/RETURNED→VOID(本人);APPROVED→VOID 需后续冲正版本,本版仅管理员+原因,且需无下游? 付款单生效后如需更正走后续冲正流程,本版先只允许草稿/退回作废)。
- 金额口径:服务端计算与分档,客户端提交值仅作参考。

## 5. 接口增量

| 接口 | 说明 |
| --- | --- |
| `GET /supply/payments/list` | 列表(含我的待办视图参数) |
| `GET /supply/payments/{id}` | 详情(含核销明细) |
| `POST /supply/payments` | 新建草稿(仅采购/管理员) |
| `PUT /supply/payments` | 编辑草稿/退回单 |
| `POST /supply/payments/{id}/submit` | 提交(服务端余额校验+分档建待办) |
| `POST /supply/payments/{id}/review` | 财务复核(通过/退回) |
| `POST /supply/payments/{id}/director-decision` | 财务总监终审(>10 万) |
| `POST /supply/payments/{id}/void` | 作废(草稿/退回本人;权限校验) |
| `GET /supply/payments/ap-balance` | 应付余额查询(供应商/发票维度) |
| `GET /supply/ledger/ap-aging` | 应付账龄(未核销按发票开票日期) |

权限:`supply:payment:query/add/edit/approve/export`;菜单:供应链 → 付款管理。

## 6. 数据范围(沿用 M2 职级)

- 采购职员(STAFF):仅本人创建的付款单(申请人);
- 采购部门领导/总监:本部门/全部(按 creator/buyer 部门);
- 财务复核/总监:以任务指派与金额分档为准,可按 V2.0 §3.2 例外(审批人可见被指定单据;财务台账全量读仅 LEADER/EXEC)。
- 应付查询(台账):按 V2.0 财务台账读规则。
