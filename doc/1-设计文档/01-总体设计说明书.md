# AllinOne 企业级报表管理系统 — 总体设计说明书

---

## 1. 四层分层架构

AllinOne 基于 RuoYi-Vue 3.9.2 框架构建，采用经典的四层分层架构，自顶向下依次为：

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│                                   展 示 层                                            │
│  Vue 3 + TypeScript + Element Plus + Pinia + Vite 6                                  │
│  ┌────────────────┐ ┌────────────────┐ ┌────────────────┐ ┌──────────────────────┐  │
│  │  填报管理页面    │ │  报表管理页面    │ │  大屏管理页面    │ │  系统管理页面(RuoYi)  │  │
│  │  Luckysheet组件 │ │  ReportFrame   │ │  BigScreenFrame│ │  用户/角色/菜单等     │  │
│  └────────────────┘ └────────────────┘ └────────────────┘ └──────────────────────┘  │
├──────────────────────────────────────────────────────────────────────────────────────┤
│                                   应 用 层                                            │
│  Spring Boot 3 Controller 层                                                          │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌────────────┐ │
│  │ Collect模块  │ │ Report模块   │ │ System模块   │ │ Quartz模块   │ │ Generator  │ │
│  │ Controller   │ │ Controller   │ │ Controller   │ │ Controller   │ │ Controller │ │
│  └──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘ └────────────┘ │
├──────────────────────────────────────────────────────────────────────────────────────┤
│                                   服 务 层                                            │
│  ┌───────────────────────────────────────────────────────────────────────────────┐   │
│  │  AOP 切面层: @Log / @DataScope / @PreAuthorize / @RepeatSubmit               │   │
│  ├───────────────────────────────────────────────────────────────────────────────┤   │
│  │  核心服务层: UserService / RoleService / MenuService / DeptService / ...      │   │
│  ├───────────────────────────────────────────────────────────────────────────────┤   │
│  │  业务服务层: CollectTemplateService / CollectDataService / ReportConfigService│   │
│  ├───────────────────────────────────────────────────────────────────────────────┤   │
│  │  第三方引擎集成: JimuReport Starter / LuckySheet数据处理                       │   │
│  └───────────────────────────────────────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────────────────────────────────────────┤
│                                   数 据 层                                            │
│  MyBatis + Druid + Redis + MySQL                                                     │
│  ┌────────────────┐ ┌────────────────┐ ┌────────────────┐ ┌──────────────────────┐  │
│  │  RuoYi系统表    │ │  填报业务表     │ │  报表配置表     │ │  Redis              │  │
│  │  sys_user等     │ │  collect_*     │ │  report_*      │ │  缓存/Token/分布式锁 │  │
│  └────────────────┘ └────────────────┘ └────────────────┘ └──────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

### 各层职责说明

| 层级 | 说明 |
|------|------|
| **展示层** | Vue 3 SPA，包含 RuoYi 原生页面 + 新增的填报/报表/大屏页面。通过 Axios 调用后端 API，通过 iframe 嵌入 JimuReport/JimuBI 设计器 |
| **应用层** | Controller 层，接受请求、参数校验、权限校验（@PreAuthorize）、日志记录（@Log），委派给 Service 层处理 |
| **服务层** | 核心业务逻辑 + AOP 切面 + 第三方引擎集成（JimuReport Starter / LuckySheet 数据处理） |
| **数据层** | MyBatis Mapper + Druid 连接池 + Redis 缓存 |

## 3. 技术选型与使用场景说明

### 3.1 RuoYi-Vue — 项目底座

| 维度 | 说明 |
|------|------|
| **为什么选它？** | RuoYi 是国内最成熟的 Spring Boot + Vue 前后端分离快速开发框架，提供开箱即用的 RBAC 权限体系（用户/角色/菜单/部门）、代码生成器（一键生成 CRUD）、操作日志、数据权限、字典管理等企业级基础能力。选用它可避免重复造轮子，大幅缩短基础功能的开发周期 |
| **什么场景下用？** | 作为整个系统的**权限底座**和**架构骨架**。所有用户登录、菜单路由、按钮级权限、数据行级权限、操作审计日志都依赖 RuoYi 框架实现。新增的填报和报表模块在此基础上扩展 |
| **怎么用？** | 本项目 fork 自 RuoYi-Vue 3.9.2 的 springboot3 分支，保留了完整的系统管理模块，采用 allinone-collect 和 allinone-report 独立子模块，通过 RuoYi 菜单管理动态注册新功能的菜单和权限 |

### 3.2 Vue 3 + TypeScript — 前端框架

| 维度 | 说明 |
|------|------|
| **为什么选它？** | Vue 3 是当前主流的前端框架，Composition API 提供更好的逻辑复用能力，TypeScript 提供类型安全，Vite 构建速度极快。与 RuoYi-Vue3-TypeScript 版本完美兼容 |
| **什么场景下用？** | 构建整个前端 SPA 应用，包括系统管理页面、数据填报页面、报表查看页面、大屏展示页面的全部 UI |
| **怎么用？** | 项目前端采用 allinone-typescript 模块，使用 `<script setup lang="ts">` 语法、Pinia 状态管理、Vue Router 4 动态路由 |

### 3.3 Element Plus — UI 组件库

| 维度 | 说明 |
|------|------|
| **为什么选它？** | Element Plus 是 Vue 3 生态最成熟的桌面端 UI 组件库，70+ 高质量组件，深度集成 TypeScript，与 RuoYi 的前端架构天然兼容。RuoYi-Vue3 版本默认使用 Element Plus |
| **什么场景下用？** | 所有后台管理页面的 UI 组件：表格（el-table）、表单（el-form）、弹窗（el-dialog）、导航菜单、分页、按钮、消息提示等 |
| **怎么用？** | 已在 main.ts 中全局注册 app.use(ElementPlus)，模板中直接使用 `<el-button>` 等组件。图标使用 `@element-plus/icons-vue` |

### 3.4 Luckysheet — 数据收集引擎

| 维度 | 说明 |
|------|------|
| **为什么选它？** | Luckysheet 是纯前端的在线电子表格组件，提供类 Excel 的全功能操作体验（公式、样式、合并单元格、数据验证、图表等）。相比传统 HTML 表单，Luckysheet 填报有三大优势：① 用户零培训成本（Excel 怎么用就怎么填）；② 支持复杂表格布局（多级表头、动态行列、交叉报表）；③ 天然支持公式自动计算 |
| **什么场景下用？** | **数据采集与填报场景**：财务报表填报（预算表、利润表）、运营数据采集（日报、周报、月报）、调查数据录入、批量数据导入等需要类 Excel 操作的数据录入场景 |
| **怎么用？** | **本地源码集成**，源码目录 `allinone-luckysheet/` 位于项目根目录。首次使用需构建：`cd allinone-luckysheet && yarn install && yarn build`，构建产物在 `dist/` 目录。前端项目中通过 Vite resolve.alias 或本地文件协议引入，组件中 import CSS/JS 资源，`onMounted` 时 `luckysheet.create()` 初始化、`onUnmounted` 时 `luckysheet.destroy()` 销毁。数据存储采用双轨制：完整 JSON 存于 `collect_data.form_data`（用于精确还原），关键字段映射回写业务表（用于统计分析） |

**Luckysheet 本地集成步骤：**

```bash
# ① 构建 luckysheet
cd allinone-luckysheet
yarn install
yarn build          # 生成 dist/ 目录

# ② 在前端项目 package.json 中添加本地依赖（二选一）
# 方式 A：file 协议引用
# "luckysheet": "file:../allinone-luckysheet"

# 方式 B：直接拷贝 dist 目录到前端项目的 public/ 目录
```

**CollectSheet.vue 中的引用方式：**

```typescript
// 方式 A：通过 npm 包名引用（已通过 file: 协议安装）
import luckysheet from 'luckysheet'
import 'luckysheet/dist/css/luckysheet.css'

// 方式 B：通过相对路径引用（未安装 npm 包时）
// import luckysheet from '../../allinone-luckysheet/dist/luckysheet.umd.js'
```

> ⚠️ **注意：** Luckysheet 2.x 官方仓库已**停止维护（archived）**，本项目采用本地源码构建方式确保可控性。新项目建议评估 [Univer](https://github.com/dream-num/univer) 作为长期替代方案。

### 3.5 JimuReport + JimuBI — 报表与可视化引擎

| 维度 | 说明 |
|------|------|
| **为什么选它？** | JimuReport（积木报表）是目前国内功能最完善的开源免费报表工具，提供类 Excel 拖拽式报表设计器、28+ 种 ECharts 图表、大屏设计器和仪表盘。相比自研报表或商业报表工具（如帆软），积木报表集成成本低、功能全面且完全免费可商用 |
| **什么场景下用？** | **三种核心场景**：① **复杂报表** — 分组报表、交叉报表、主子报表、多表头报表，支持数据钻取和预警高亮；② **数据大屏** — 领导驾驶舱、运营监控中心，拖拽式设计、支持 3D 地图；③ **仪表盘** — 日常数据监控看板，PC/手机双模式 |
| **怎么用？** | 通过 Maven 依赖引入 Spring Boot Starter（需添加包扫描 `org.jeecg`），前端通过 iframe 嵌入报表设计器和大屏设计器。Token 鉴权需实现积木报表提供的 `JmReportTokenServiceI` 接口（注入 RuoYi 的 `TokenService` 进行 JWT 校验），不可简单在 URL 中传递 Token。Security 放行 `/jmreport/**` 和 `/jmbi/**` 路径 |

## 4. 数据流转全景

### 4.1 数据采集→存储→展示 完整流向

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  数据采集      │     │  数据存储      │     │  数据展示      │
│  Luckysheet   │     │  MySQL/Redis  │     │  JimuReport  │
│              │     │              │     │              │
│  ① 创建模板   │ ──→ │  collect_     │ ──→ │  报表渲染     │
│  ② 在线填报   │     │  template    │     │  大屏渲染     │
│  ③ 保存草稿   │     │  collect_    │     │  仪表盘      │
│  ④ 提交数据   │     │  data        │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
       │                    │                    │
       └────────────────────┴────────────────────┘
                       RuoYi 权限管控贯穿全链路
                  (@PreAuthorize / @DataScope / @Log)
```

### 4.2 JimuReport 与 RuoYi 的数据关系

- **共用数据库：** JimuReport 的数据表（`jimu_report`、`jimu_report_data_source` 等）与本项目的业务表共享同一个 MySQL 数据库
- **数据源配置：** JimuReport 在报表设计器中直接选择本项目已配置的 Druid 数据源（master），使用参数化 SQL 查询业务数据
- **报表集成：** 本项目通过 `report_config.jimu_report_id` 字段关联 JimuReport 的内部报表记录，实现菜单挂载和权限控制

### 4.3 JimuReport 集成注意事项

| 注意项 | 说明 |
|--------|------|
| **Maven 依赖** | 添加 `jimureport-spring-boot-starter`（需指定与 Spring Boot 3.x 兼容的版本） |
| **包扫描** | `@SpringBootApplication` 必须包含 `"org.jeecg"` 包路径 |
| **初始化 SQL** | 首次集成必须执行 JimuReport 官方提供的 `jeecg_report_*.sql` 建表脚本 |
| **minidao 配置** | 需在 `application.yml` 中添加：`minidao.base-package: org.jeecg.modules.jmreport.desreport.dao*` |
| **Security 放行** | 使用 `requestMatchers("/jmreport/**", "/jmbi/**").permitAll()`（注意不可用已移除的 `antMatchers`） |
| **Token 鉴权** | 实现 `JmReportTokenServiceI` 接口，注入 RuoYi 的 `TokenService` 进行 JWT 校验（详见功能模块设计文档） |
| **版本兼容** | JimuReport 2.5.0+ 支持 Spring Boot 3.x，低版本需确认兼容性 |

### 4.3 Luckysheet 填报数据流向

1. **管理员** 在填报模板编辑页打开 Luckysheet，设计表头、样式、公式等，保存为模板
2. **模板 JSON** 存入 `collect_template.template_json`（longtext 字段）
3. **填报人** 选择模板 → 前端深拷贝模板 JSON 并清空数据单元格 → 渲染 Luckysheet
4. **填报数据** 以 JSON 快照形式存入 `collect_data.form_data`
5. **提交或审批通过后**（可选），数据回写引擎按字段映射配置，将单元格数据写入对应的业务表
6. **JimuReport** 通过 SQL 数据集查询业务表数据，渲染为报表或大屏

## 6. 安全配置

### 6.1 CORS 跨域配置

```java
// 生产环境需指定精确域名，开发环境可用 allowAllOrigins
@Bean
public CorsFilter corsFilter() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOriginPatterns(Arrays.asList("*"));
    config.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE"));
    config.setAllowedHeaders(Arrays.asList("*"));
    config.setAllowCredentials(true);
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return new CorsFilter(source);
}
```

### 6.2 X-Frame-Options 策略

因系统通过 iframe 嵌入 JimuReport 报表和大屏，需配置同源 iframe 放行：

```java
// 全局 DENY，仅报表路径 SAMEORIGIN
httpSecurity.headers(headers -> headers
    .frameOptions(frameOptions -> frameOptions
        .sameOrigin()
    )
);
// 或在 ResourcesConfig 中按路径控制
```

### 6.3 XSS 防护

对 Luckysheet 渲染数据做 HTML 转义处理，用户输入字段做白名单校验，复用 RuoYi 内置的 XSS 过滤器。

## 7. 错误处理策略

### 7.1 统一错误响应格式

```json
{
  "code": 500,
  "msg": "业务异常描述",
  "data": null
}
```

### 7.2 错误码体系

| 错误码 | 说明 |
|:------:|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未认证/Token 过期 |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
| 1001 | 填报模板不存在 |
| 1002 | 模板未发布不可用 |
| 1003 | 数据状态不允许修改 |
| 1004 | 数据版本冲突（乐观锁） |

### 7.3 事务管理

填报数据提交时涉及多表写入，需使用声明式事务：

```java
@Transactional(rollbackFor = Exception.class)
public AjaxResult submit(CollectData data) {
    // 1. 校验数据
    // 2. 保存 form_data
    // 3. 更新业务状态
    // 4. （可选）数据回写业务表
}
```
