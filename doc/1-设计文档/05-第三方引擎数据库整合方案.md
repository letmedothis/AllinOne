# AllinOne 企业级报表管理系统 — 第三方引擎数据库整合方案

---

## 1. 整合全景

本项目在 RuoYi 基座之上集成了 JimuReport（积木报表/大屏）和 Luckysheet（在线表格）。各引擎有自己的数据库表，需要与 RuoYi 基座的表进行整合。

所有表共用同一 MySQL 数据库实例，通过表名前缀隔离：
- RuoYi 基座表: sys_user, sys_role, sys_menu, sys_dept, sys_dict, sys_oper_log
- JimuReport 表: jimu_report, jimu_report_data_source, jimu_report_db, jimu_dict, onl_drag_*(大屏)
- AllinOne 业务表: collect_template, collect_data, collect_data_cell, collect_category, collect_field_mapping, report_config, report_category

### 2.3 管理说明

根据 JimuReport 官方文档：jimu_* 是 JimuReport 的表，onl_drag_* 是 JimuBI 的表。均由引擎自动管理，
开发者无需为这些表编写 Mapper 或 Service，也不应手动修改其表结构。

## 3. 整合痛点与解决方案

### 痛点1: 字典重复 (jimu_dict vs sys_dict)
保持独立，互不干扰。JimuReport字典仅用于报表设计器内部。

### 痛点2: 用户身份一致性
JmReportTokenServiceI.getUsername()返回LoginUser.getUsername()。

### 痛点3: 逻辑删除差异
RuoYi用char(1)('0'/'2')，JimuReport用tinyint(1)。各自管理无影响。

### 痛点4: 主键策略
RuoYi用bigint，JimuReport用varchar(32)。report_config用varchar(64)兼容。

### 痛点5: 数据源配置
手动配置或自动发现Druid Bean。

## 4. 跨引擎兼容性

### report_config双字段关联
- type=0(报表): jimu_report_id -> jimu_report.id
- type=1(大屏)/2(仪表盘): jmbi_id -> onl_drag_page.id

### 三层存储架构(Luckysheet -> JimuReport)
- Tier1: collect_data.form_data(JSON) - 精确还原
- Tier2: collect_data_cell - SQL灵活查询
- Tier3: biz_xxx - 字段映射回写

## 5. JmReportTokenServiceI 鉴权集成

根据官方文档(https://help.jimureport.com/config/token/)，需实现JmReportTokenServiceI接口。

需要实现的方法:
1. getToken(HttpServletRequest) - 从参数或Header提取Token
2. verifyToken(String token) - 校验Token有效性
3. getUsername(String token) - 获取用户名
4. getTenantId() - 获取租户ID
5. getRoles(String token) - 返回用户角色
6. getPermissions(String token) - 返回权限指令

Token传递方式:
- URL参数: ?token=${jwt}
- Header: X-Access-Token (兼容JeecgBoot)
- Header: token
