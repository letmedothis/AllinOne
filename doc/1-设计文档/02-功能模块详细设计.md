## 模块一：数据填报模块（基于 Luckysheet）

### 使用场景

业务人员需要在线填报数据，例如：
- **财务报表填报**：预算执行表、利润表、现金流量表等复杂表格
- **运营数据采集**：日报/周报/月报、销售数据录入、库存盘点
- **调查问卷**：市场调研、客户满意度调查
- **批量数据录入**：历史数据补录、Excel 数据批量导入

利用 Luckysheet 的**类 Excel 操作体验**，填报人员无需培训即可上手，大幅降低推广成本。同时支持公式自动计算、数据验证、多 Sheet 等高级功能，满足复杂填报场景。

### 功能清单

#### 1.1 填报模板管理

| 功能 | 说明 |
|------|------|
| 模板 CRUD | 创建、修改、删除、查询填报模板（模板名称、编码、分类归属） |
| Luckysheet 设计器嵌入 | 创建/编辑模板时，打开 Luckysheet 在线表格设计器，支持设置表头、样式、公式、数据验证、冻结行列、合并单元格、多 Sheet |
| 模板发布/下架 | 发布后用户才可见并可填报；下架后用户只能查看已有数据，不能新增填报 |
| 版本管理 | 每次修改并发布时自动递增版本号，用户填报时使用当前发布版本的模板 |
| 模板预览 | 以只读模式预览模板效果 |
| 模板复制 | 快速克隆已有模板创建新模板 |

**权限设计：**

| 权限标识 | 说明 |
|---------|------|
| `collect:template:list` | 查看模板列表 |
| `collect:template:query` | 查看模板详情 |
| `collect:template:add` | 新增模板 |
| `collect:template:edit` | 修改/设计/发布模板 |
| `collect:template:remove` | 删除模板 |

#### 1.2 数据填报

| 功能 | 说明 |
|------|------|
| 在线填报 | 用户选择已发布模板 → 打开 Luckysheet 在线表格 → 填写数据 |
| 草稿自动保存 | 每 30 秒自动保存到 `collect_data.form_data`，防止数据丢失 |
| 草稿手动保存 | 用户点击"保存草稿"按钮手动保存 |
| 数据提交 | 填写完成后提交，状态由"草稿"变为"已提交"，提交后不可再修改 |
| 数据校验 | 基于模板中配置的数据验证规则，提交时逐单元格校验（必填项、格式、范围、公式等） |
| 字典下拉绑定 | 单元格可绑定 RuoYi 字典，填报时以下拉框形式选择字典值 |
| 批量导入 Excel | 支持将本地 Excel 数据导入到填报表格中 |

#### 1.3 版本兼容性策略

| 场景 | 策略 |
|------|------|
| 模板修改后已有草稿 | 已有草稿继续使用旧版模板渲染，不影响用户正在编辑的内容 |
| 模板修改后已提交数据 | 已提交数据保留提交时的 JSON 快照，与最新模板无关 |
| 用户打开模板时 | 始终使用当前已发布的最新版本模板 JSON |
| 历史数据回看 | 使用 `collect_data.form_data` 中保存时的快照还原展示 |

**实现方式：** 采用"模板代码 + 数据快照分离"方案——`collect_template` 只存当前的模板定义，`collect_data.form_data` 存提交时的完整数据快照。查看历史数据时直接回放快照，不受模板变更影响。

#### 1.4 并发与数据一致性

| 问题 | 解决方案 |
|------|---------|
| 多人同时编辑同一数据 | 本系统采用"一人一条数据"模式，不同填报人各自拥有独立数据记录，不存在多人编辑同一数据的冲突 |
| 自动保存覆盖问题 | 自动保存是增量保存（同一用户对自己数据的保存），不存在覆盖他人数据的问题 |
| 提交时数据过期 | 通过前端乐观锁实现：提交时比较 `update_time`，若提交时间与最新保存时间间隔超过阈值则提示刷新 |
| 防重复提交 | 使用 RuoYi 的 `@RepeatSubmit` 注解防止用户快速双击导致重复提交 |

#### 1.5 数据管理

| 功能 | 说明 |
|------|------|
| 我的填报 | 查看自己提交的所有数据列表，按模板/状态/时间筛选 |
| 数据修改 | 仅"草稿"状态可修改；"已提交"状态只读 |
| 数据详情查看 | 以只读 Luckysheet 回放数据快照 |
| 数据删除 | 删除填报数据（逻辑删除） |
| 数据导出 | 支持按模板/状态/时间筛选后导出为 Excel |

**导出策略：**
- 小数据量（< 1 万行）：同步导出，直接返回 Excel 文件
- 大数据量（≥ 1 万行）：异步导出，创建导出任务，完成后通知下载
- 单次导出上限：10 万行，导出文件 24 小时后自动清理

**数据校验策略（前后端双重校验）：**
- **前端校验：** 利用 Luckysheet 数据验证功能，提交时即时校验
- **后端校验：** Service 层独立执行校验（必填/数据类型/字典合法性/公式结果），防止绕过前端调用 API
- 校验规则存储在 `collect_template_validation` 表中（V2.0 扩展）

**权限设计：**

| 权限标识 | 说明 |
|---------|------|
| `collect:data:list` | 查看填报数据列表 |
| `collect:data:query` | 查看填报数据详情 |
| `collect:data:add` | 新增/草稿保存填报数据 |
| `collect:data:edit` | 修改填报数据 |
| `collect:data:remove` | 删除填报数据 |
| `collect:data:export` | 导出填报数据 |

| `collect:category:add` | 新增分类 |

#### 1.7 与 RuoYi 的集成

| 集成点 | 实现方式 |
|--------|---------|
| **菜单挂载** | 通过 RuoYi 菜单管理添加填报模块菜单：目录"数据填报"→ 菜单"填报模板"/"我的填报" |

#### 1.8 字段映射管理

字段映射是三层存储架构中 Tier 3（业务层）的核心配置。用户提交填报数据时，数据回写引擎根据此配置将 Luckysheet 单元格坐标 (row, col) 对应的值提取出来，写入目标业务表（如 biz_budget）的指定字段。

| 功能 | 说明 |
|------|------|
| 映射 CRUD | 创建/修改/删除/查询（坐标 → 表.列） |
| 按模板查询 | 查询某模板下所有映射，按 order_num 排序 |
| 目标表分组 | 一次提交可同时回写多个业务表 |
| 主键标记 | pk_order>0 用于 UPSERT 判断 |

**权限标识：** collect:mapping:list / query / add / edit / remove

**后端实现：** CollectFieldMappingController, ICollectFieldMappingService, CollectFieldMappingMapper

#### 1.9 数据回写引擎（三层架构 Tier 3）

提交数据时自动执行三层存储：

| 层级 | 表 | 用途 |
|:----:|----|------|
| T1 快照 | collect_data.form_data (JSON) | 页面精确还原 |
| T2 单元格 | collect_data_cell | 明细查询（JimuReport SQL） |
| T3 业务 | biz_xxx（字段映射写入） | 业务报表（JimuReport SQL） |

图片上传：CollectSheet 组件自动拦截 Luckysheet 的图片插入，通过 POST /common/upload 上传至服务器，在单元格中存储 URL 而非 base64，避免 form_data 膨胀。配置见 application.yml 中 allinone.file 段。

## 模块二：报表管理模块（基于 JimuReport）

### 使用场景

企业内部需要各种格式的数据报表，例如：
- **业务报表**：销售汇总表、客户订单明细、库存清单
- **统计图表**：月度趋势图、占比饼图、对比柱状图
- **票据打印**：发货单、对账单、收据套打
- **数据导出**：将报表导出为 Excel/PDF 分发给相关方

JimuReport 提供**类 Excel 拖拽式报表设计**，非技术人员也能自行设计报表，降低对开发团队的依赖。

### 功能清单

#### 2.1 报表配置管理

| 功能 | 说明 |
|------|------|
| 报表 CRUD | 创建、修改、删除、查询报表配置（报表名称、编码、类型、关联 JimuReport ID） |
| 报表分类管理 | 树形分类组织报表，如"运营报表/财务报表/人力资源" |
| 报表类型 | 支持三种类型：常规报表(0)、大屏(1)、仪表盘(2) |
| 图标和排序 | 配置报表菜单图标和同级排序顺序 |

#### 2.2 报表查看

| 功能 | 说明 |
|------|------|
| iframe 嵌入 | 报表页面通过 iframe 嵌入 JimuReport 渲染的报表内容，URL 中传递 JWT Token 实现认证 |
| 全屏展示 | 报表支持全屏查看模式 |
| 多格式导出 | 支持导出为 PDF、Excel、Word、图片格式 |
| 参数查询 | 报表运行时可输入参数（如日期范围、部门等）筛选数据 |
| 数据钻取 | 点击报表中的数据可下钻查看明细 |

#### 2.3 权限设计

| 权限标识 | 说明 |
|---------|------|
| `report:config:list` | 查看报表配置列表 |
| `report:config:query` | 查看报表配置详情 |
| `report:config:add` | 新增报表配置 |
| `report:config:edit` | 修改报表配置 |
| `report:config:remove` | 删除报表配置 |

**数据行级权限说明：**
- 报表的**菜单可见性**由 RuoYi `@PreAuthorize` 控制（按钮级权限）
- 报表的**数据行级过滤**（如：经理只看本部门数据，CEO 看全部）**不由** `@DataScope` 控制
- 行级过滤通过 JimuReport SQL 参数注入实现：报表 SQL 中写 `dept_id = #{dept_id}`，引擎自动替换为当前用户部门ID
- 具体实现依赖 `JmReportTokenServiceI.getUserInfo()` 传递用户部门/角色上下文（详见整合方案 §5.2）

#### 2.4 与 RuoYi 的集成

| 集成点 | 实现方式 |
|--------|---------|
| **菜单挂载** | 通过 RuoYi 菜单管理添加报表菜单，菜单类型选择 iframe，内嵌 JimuReport 地址 |
| **Token 鉴权** | 实现 `JmReportTokenServiceI` 接口，注入 RuoYi 的 `TokenService` 进行 JWT 校验，iframe URL 中传递 Token 参数 |
| **Security 放行** | 配置 `requestMatchers("/jmreport/**", "/jmbi/**").permitAll()` |
| **同源支持** | 配置 `frameOptions().sameOrigin()` 允许同源 iframe 加载 |

**Token 鉴权的正确实现方式：**

积木报表官方提供的鉴权扩展点是 `JmReportTokenServiceI` 接口（位于 `org.jeecg.modules.jmreport.api` 包），需要编写实现类注入 Spring 容器：

```java
package com.allinone.framework.jimureport;

import com.allinone.framework.web.service.TokenService;
import org.jeecg.modules.jmreport.api.JmReportTokenServiceI;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import javax.servlet.http.HttpServletRequest;
import java.util.Map;

/**
 * JimuReport 鉴权集成
 * 实现 JmReportTokenServiceI 接口，对接 RuoYi 的 TokenService
 * 官方文档: https://help.jimureport.com/config/token.html
 */
@Component
public class JimuReportTokenService implements JmReportTokenServiceI {

    @Autowired
    private TokenService tokenService;

    /**
     * 从 HttpServletRequest 中提取 Token 令牌
     */
    @Override
    public String getToken(HttpServletRequest request) {
        // 从参数或 Header 中获取 Token
        String token = request.getParameter("token");
        if (token == null || token.isEmpty()) {
            token = request.getHeader("X-Access-Token");
        }
        if (token == null || token.isEmpty()) {
            token = request.getHeader("token");
        }
        return token;
    }

    /**
     * 校验 Token 有效性
     */
    @Override
    public Boolean verifyToken(String token) {
        try {
            String username = tokenService.getUsernameFromToken(token);
            return username != null;
        } catch (Exception e) {
            return false;
        }
    }

    /**
     * 根据 Token 获取用户名
     */
    @Override
    public String getUsername(String token) {
        return tokenService.getUsernameFromToken(token);
    }

    // ===== 以下为可选方法（按需实现）=====

    @Override
    public String[] getRoles(String token) {
        // 可选：返回用户角色列表，用于报表设计器中的权限控制
        return new String[0];
    }

    @Override
    public String[] getPermissions(String token) {
        // 可选：返回用户权限指令列表
        return new String[0];
    }
}
```

> **注意：** 若依使用 Spring Security，JimuReport 的 `/jmreport/**` 路径需在 SecurityConfig 中放行，报表内部的鉴权由 `JmReportTokenServiceI` 实现类全权控制。

前端 iframe URL 拼接方式：
```vue
<iframe :src="`/jmreport/view/${reportId}?token=${token}`" />
```


**JmReportTokenServiceI 方法列表（官方接口）：**

| 方法 | 返回值 | 说明 |
|------|--------|------|
| getToken(HttpServletRequest) | String | 从请求中提取 Token（参数/Header） |
| verifyToken(String token) | Boolean | 校验 Token 有效性 |
| getUsername(String token) | String | 根据 Token 获取用户名 |
| getTenantId() | String | 获取当前租户ID |
| getRoles(String token) | String[] | 获取用户角色列表（报表权限控制） |
| getPermissions(String token) | String[] | 获取用户权限指令列表 |

**JimuBI 大屏鉴权接口：** 使用 `JimuDragExternalServiceImpl` 类实现，参照 JeecgBoot 官方实现。

**Token 传递方式（官方支持三种）：**

| 方式 | 示例 |
|------|------|
| URL 参数 | /jmreport/view/xxx?token=${jwt} |
| Header (JeecgBoot) | X-Access-Token: ${jwt} |
| Header (通用) | token: ${jwt} |

程序获取 token 后会自动放入请求 Header 中，后续接口通过 Header 接收 Token 进行权限验证。

**权限指令列表（JimuReport v1.9.3+）：**

| 权限指令 | 功能说明 |
|---------|---------|
| drag:datasource:testConnection | 仪表盘数据库连接测试 |
| onl:drag:clear:recovery | 仪表盘清空回收站 |
| drag:analysis:sql | 仪表盘 SQL 解析 |
| drag:design:getTotalData | 仪表盘对 Online 表单展示数据 |

**Spring Boot 3.x Security 放行配置：**
```java
// Spring Security 6.x 语法 - 不可使用已移除的 antMatchers
.requestMatchers("/jmreport/**", "/drag/**", "/jimubi/**").permitAll()
```

## 模块三：大屏管理模块（基于 JimuBI）

### 使用场景

企业数据可视化大屏展示，例如：
- **领导驾驶舱**：实时展示核心经营指标
- **运营监控中心**：监控业务运行状态、异常预警
- **汇报演示**：用于年度总结、项目汇报、展厅展示

JimuBI 提供 **28+ 种可视化组件**和拖拽式设计器，支持 3D 图表、地图组件、数据定时刷新，无需编码即可设计专业的数据大屏。

### 功能清单

#### 3.1 大屏配置管理

| 功能 | 说明 |
|------|------|
| 大屏 CRUD | 通过 JimuBI 设计器创建大屏，在本系统配置关联映射 |

| 数据源配置 | 支持 SQL 查询、API 接口、JSON 静态数据、WebSocket 实时数据 |

#### 3.2 大屏查看与分享

| 功能 | 说明 |
|------|------|
| 全屏展示 | 大屏以全屏模式呈现，适合在电子屏幕或投影上展示 |
| 密码保护 | 可设置查看密码，仅授权人员可访问 |

#### 3.3 权限设计

大屏权限复用报表管理的权限体系，与报表共用 `report:config:xxx` 权限标识，通过 `report_type` 字段区分报表和大屏。

## 模块四：系统集成（RuoYi 底座能力复用）

### 4.1 菜单管理

新的功能模块通过 RuoYi **系统管理 → 菜单管理**注册，无需编码路由：

| 菜单类型 | 用途 | 示例 |
|---------|------|------|
| **目录** | 功能模块分组 | "数据填报"目录下面的"报表管理"目录 |
| **菜单** | 页面入口 | "填报模板"菜单指向 `/collect/template` |
| **按钮** | 操作权限 | "新增"按钮对应 `collect:template:add` |

### 4.2 权限控制体系

```
@PreAuthorize                  → 后端接口级权限（Controller 层）
@PreAuthorize("@ss.hasPermi('collect:data:submit')")

v-hasPermi                    → 前端按钮级权限（Vue 模板层）
<el-button v-hasPermi="['collect:data:submit']">提交</el-button>

@DataScope(deptAlias = "cd")  → 数据行级权限（Mapper 层）
自动拼接：AND cd.dept_id IN (用户管辖部门ID)
```

### 4.3 日志与审计

使用 `@Log` 注解记录所有关键操作，自动入库 `sys_oper_log`：

```java
@Log(title = "填报数据", businessType = BusinessType.INSERT)
public AjaxResult add(@RequestBody CollectData collectData) { ... }
```

### 4.4 代码生成器加速开发

新建业务表后，通过 RuoYi 代码生成器：
1. 导入表结构 → 2. 编辑字段配置 → 3. 生成代码 → 4. 解压到对应模块
5. 在此基础上修改，增加 Luckysheet 集成等定制逻辑

**适用于：** 基础 CRUD 的 Controller/Service/Mapper/XML/Vue 页面生成

## 模块五：工作流（后续迭代规划）

当前版本**不引入**工作流引擎，填报数据的审批通过 `biz_status` 字段的状态流转来实现基本的"草稿→已提交"管理。

**后续迭代（V2.0）将引入 Warm-Flow 实现：**
- 填报数据提交后自动发起审批流程
- 审批人通过/驳回操作
- 审批中数据锁定不可编辑
- 审批通过后数据自动归档
- 待办任务列表和审批进度查看
