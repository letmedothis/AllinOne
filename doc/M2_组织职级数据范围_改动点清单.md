## 1. 现状画像(盘点结论)

### 1.1 当前数据范围实现(全部为"角色硬编码 + 本人"二分)

| 模块 | 列表/台账过滤(XML) | 详情校验(Service) |
| --- | --- | --- |
| 供应商 | `supplyGlobal`(supervisor/purchasing_supervisor/purchase_supervisor/finance 任一角色=true)→ 全局;否则 `creator=me` 或 `po.buyer=me`(SupplierMapper.xml:42) | `requireVisible`:全局角色放行,否则仅 creator(SupplierServiceImpl:169) |
| 采购订单 | `supplyGlobal` 或 `creator=me` 或 `buyer=me`(PurchaseOrderMapper.xml:39) | `requireVisible`(creator 或 buyer);编辑/提交 `requireOwner` |
| 发票 | `admin=true` 或 `creator=me` 或 `po.buyer=me` 或 任务 assignee/acted=me(InvoiceMapper.xml:16) | Service 组合 admin/global 布尔入参 |
| 入库单 | 无列表查询;工作台按 `admin`/`creator` 计数(SupplyDashboardMapper.xml) | — |
| 综合台账 | `#{admin}=true` 或 `creator=me` 或 `buyer=me`(LedgerMapper.xml:16) | LedgerService 计算入参 |
| 工作台 | 各金额/计数子查询按 `admin`/`creator`(SupplyDashboardMapper.xml) | — |
| 审批中心 | 待办=assignee 本人(workflow_tasks),与数据范围无关 | 需保证审批人可读单据 |

### 1.2 角色事实

- 供应链代码依赖 role_key:`purchaser`(采购员资格)、`supervisor/purchasing_supervisor/purchase_supervisor`(主管资格+全局范围)、`finance`(财务+全局范围)。
- **仓库无任何 role_key/部门**,库存 SQL 未发现这些 role_key 的定义/种子(演示环境由线下手工配置角色)。`supply_demo_seed.sql` 不创建用户/角色,只用会话变量指定审批人。

## 2. 目标模型(V2.0 §2/§3 落地)

- 数据范围判定维度 = **`sys_user.rank_level`**(新增列,可空):
  - `EXEC` 总监 → 全部业务单据;
  - `LEADER` 部门领导 → 本部门(不含下级);
  - `STAFF` 职员 → 本人创建/被指派;
  - `NULL`(未配置,过渡期)→ 沿用旧角色逻辑(全局角色放行),**避免未配职级时功能回退**。
- 部门归属:`documents.creator_id → sys_user.dept_id`(仓库/订单采购员同部门场景用 buyer 兜底)。
- 例外:
  1. 仓储部职员/负责人:可读**已批准订单必要字段**与全部入库记录(收货作业),不可见发票/付款;
  2. 审批人:被指派任务可读对应单据,不受范围限制;
  3. admin(信息部系统管理员):全部(运维)。

## 3. 文件级改动点(预估)

### 3.1 SQL
| 文件 | 改动 |
| --- | --- |
| `allinone_biz_update.sql` | 幂等 `ALTER TABLE sys_user ADD COLUMN rank_level varchar(16) NULL AFTER post_id`(可空=过渡) |
| `sql/supply_org_rank_seed.sql`(新增,可选) | 演示组织/职级赋值:四部门(采购/财务/信息/仓储)+按会话变量给既有用户赋 rank_level + 期初仓储演示用户;注释说明真实企业由管理员在系统内维护 |

### 3.2 后端
| 文件 | 改动 |
| --- | --- |
| 新增 `supply/support/DataScopeResolver.java`(或并入 common 工具) | 输入登录用户 → 输出 `mode=ALL/DEPT/SELF/LEGACY` + `deptId/userId`,封装 isAdmin/rank 解析与旧角色回退 |
| `SupplierServiceImpl` + `SupplierMapper.xml` | 列表条件改为:ALL 无过滤 / DEPT creator∈本部门(或 buyer∈本部门)/ SELF 现值;详情 requireVisible 同步 |
| `PurchaseOrderServiceImpl` + `PurchaseOrderMapper.xml` | 同上;DEPT 覆盖 creator∈部门 或 buyer∈部门 |
| `InvoiceServiceImpl` + `InvoiceMapper.xml` | 同上 + 任务参与人可见保留 |
| `ReceiptServiceImpl/Mapper`(新增列表)+ Dashboard/Ledger | 工作台/台账/入库查询按同一 Resolver 条件化 |
| `ApprovalServiceImpl` | 审批人详情读取不受范围限制(现有 approve/reject 走任务校验即可) |
| `selectApprovedSupplierOptions`(下单下拉) | 采购部职员也能选已准入供应商(V1.0 3.3 既定),维持现状或按 STAFF 放行 |

### 3.3 前端/权限
- 除必要按钮权限(仓库可见性外)基本不动;职级数据范围全在后端,前端不感知。
- 若需前端按职级隐藏,读 `/getInfo` 的 user 扩展字段(后续按需)。
